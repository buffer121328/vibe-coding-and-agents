# 第四章：Dify 工作流实战

本章使用 [Dify](https://dify.ai/)搭建「面必过」求职助手，包含模拟面试和简历优化两条流程。学习重点是任务如何拆分、节点之间传递什么，以及多轮对话怎样保存和结束。案例名称不代表求职结果保证。

## 开始前的准备

准备一个可用的 Dify 工作区，以及能正常调用的模型。先用虚构或脱敏简历练习，模型和导出插件分别验证通过后，再运行完整案例。界面截图对应编写时的环境，入口名称可能随版本变化。

## 阅读顺序

1. **[4.1 Dify 核心概念与平台功能](./01_Dify核心概念与平台全貌.md)**
   - 理解节点的职责，区分本次输出、会话状态和模型记忆。
2. **[4.2 创建应用：空白画布、模板与 DSL 导入](./02_创建工作流与工作室实操.md)**
   - 选择应用类型，检查导入后的模型、凭据、变量与文件输入。
3. **[4.3 模型供应商与工具插件](./03_模型供应商与工具插件生态.md)**
   - 按任务验证模型效果，区分连接失败与参数、格式问题。
4. **[4.4 认识「面必过」求职助手](./04_实战面必过工作流.md)**
   - 沿着用户路径认识两条业务流程，明确状态变量的用途。
5. **[4.5 会话状态、意图识别与分支路由](./05_状态锁路由与意图识别分流.md)**
   - 校验分类结果，处理结束、切换和未知意图。
6. **[4.6 模拟面试与问答复盘](./06_模拟面试流与多专家技术复盘.md)**
   - 保留问答依据，处理未回答问题、提前结束和历史增长。
7. **[4.7 简历评审、修改与导出](./07_多专家圆桌式简历优化流水线.md)**
   - 合并多份意见，保留事实依据，检查导出后的页面。
8. **[4.8 工作流调试、发布与验收](./08_工作流调试发布与端到端自测.md)**
   - 建立固定用例，记录失败节点，验证发布版本与接口接入。

## 配套文件与练习方式

- [求职助手 DSL](./面必过chatbot%20.yml)：导入为练习副本，检查模型、插件和变量绑定后运行。
- [截图与流程图](./img/)：对照节点位置、配置与运行结果。

第一次先走通一条面试路径，再验证简历优化。之后加入缺少材料、提前结束、切换任务和导出失败等用例。节点越多不代表效果越好；每增加一步，都应能说明它解决了什么问题。

完成本章时，应能独立解释一份输入经过哪些节点、状态在哪里保存、出错后从哪里排查，并用固定用例比较一次修改前后的结果。

## 建议保留一份练习记录

这一章的重点不只是把案例运行起来，还要能说明一条输入经过了哪些节点、哪些状态跨轮次保存、失败时在哪里结束。每完成一节，可以用下面的格式记一条实际结果：

| 记录项 | 示例内容 |
| --- | --- |
| 本次改动 | 调整意图枚举，增加未知结果分支 |
| 固定输入 | 明确任务、含糊请求、切换任务各一条 |
| 观察位置 | 节点输出、会话变量、最终回复 |
| 验收结果 | 哪些通过，哪些仍需修改 |
| 环境信息 | 模型、插件版本与运行日期 |

阅读顺序上，4.1—4.3 先建立平台、应用和外部能力的边界；4.4—4.7 沿完整案例理解路由、状态和多节点协作；4.8 再把前面的用例整理成可重复的发布检查。这样学完后留下的是一套可以迁移到其他工作流的判断方法，而不只是某一份画布配置。
