# 16 综合实战：全能旅行助手项目（全章收官）

前面十五节，我们把 LangGraph 的零件一个个拆开学了一遍：状态图、条件路由、Send 并行、流式调试、Checkpointer、Store 记忆、RetryPolicy、子图、interrupt、Functional API……这一节是全章的**装机现场**：把这些零件装进一个真实可运行的**生产架构导向教学项目**——智能旅行管家（Trip Assistant），既看清它们如何配合，也明确这台教学样机离正式生产系统还有多远。

> **💡 代码位置指引**：
> 本实战的完整代码在本章 `code/travel_agent_v2/` 目录下（含 [README](code/travel_agent_v2/README.md)、`requirements.txt` 与 `.env.example`），并针对 LangGraph 1.x 做了现代化迭代：租车真子图、Send 并行比价、Store 偏好记忆、只读节点重试，以及节点内 `interrupt()` 结构化审批。代码已脱敏，并自带无需 API Key 的机制与 Web 测试。

## 1. 项目全貌（它能干什么？）

这个项目模拟了一个真实旅游平台的客服场景：一个 SQLite 本地库存放航班、酒店、租车和旅游路线的虚拟数据。用户只需一句：

> “帮我把下周二飞东京的航班退了，改签到周三，顺便在机场附近订一辆带儿童座椅的SUV。”

整个 Multi-Agent 体系会自动完成：
1. **主助理**识别出多个意图（09 节的 Routing 模式）。
2. 路由到**航班助理**，查询退改签政策（`lookup_policy` 向量检索工具），尝试调用 `update_ticket_to_new_flight`。
3. 敏感工具先进入审批节点，`interrupt()` 把工具名、参数和调用 ID 打包后**挂起线程**（13 节的 Human-in-the-loop）。
4. 确认后完成改签，航班助理调用 `CompleteOrEscalate` 退回主助理（07 节的状态栈弹栈）。
5. **主助理**接着路由到**租车助理**，搜索周三的 SUV。
6. 走完整个流转后，主助理统一回复用户（05 节的流式输出全程可见）。

## 2. 核心代码结构剖析

进入 `code/travel_agent_v2`，你会看到一个按生产系统思路拆层、但保留本地教学依赖的 Agent 工程目录：

- 📁 `core/`（大脑图谱层与状态管理）
  - `state.py`：定义了 `State` 和 `dialog_state` 状态栈。它是整个项目的血液。
  - `llm_config.py`：大模型的统一初始化入口（通过 `.env` 环境变量切换 GPT / DeepSeek / Claude 兼容服务）。
  - `primary_agent.py`：主助理（大堂经理）的 Prompt 和路由逻辑。
  - `sub_agents.py`：四个子助理（机票、酒店、租车、游览）的专有 Prompt 与工具池。
  - `graph_builder.py`：拼装厂——三个平铺的子工作流、租车**真子图**，以及 Send 并行比价子图。
  - `memory_store.py`：长期记忆 Store（跨会话的用户偏好档案）。
  - `models.py`：Pydantic 数据模型，包括路由转交意图工具（含 `ToMultiQuote`）。
- 📁 `tools/`（手脚工具层）
  - `flights.py`、`hotels.py` 等：用 `@tool` 装饰器编写的真实 Python 函数，操作 SQLite 数据库。
  - `preferences.py`：用户偏好的记忆工具（`save_preference` / `recall_preferences`，`InjectedStore` 注入）。
  - `tool_handler.py`：工具的统一容错封装（08 节讲的 `with_fallbacks` 机制）。
  - `retriever_vector.py`：航司政策 FAQ 的向量检索（`lookup_policy` 工具，懒加载）。
- 📁 `tests/`：三层冒烟测试（全部无需 API Key）——`test_new_mechanisms.py` 处理函数层（假模型端到端驱动子图中断恢复、Store 读写与 Send 并行）、`test_web_api.py` HTTP 层（TestClient 逐端点断言）、`smoke_real_server.py` 真实服务层（线程起 uvicorn + urllib）。
- 📁 `db/`（虚拟数据库层）：`travel*.sqlite` 测试数据库。
- `main.py`：主运行文件，`build_graph()` 装配总 `StateGraph`（挂 Checkpointer 与 Store），`main()` 启动终端对话。
- 📁 `web/` + `static/`：Web 前端——FastAPI 后端 + Air 服务端 HTML 框架（Air 用 Python 类生成页面，构建在 FastAPI 之上）：`web/api.py` 是 JSON 接口（Pydantic 校验请求体、`/docs` 自动文档），`web/views.py` 是 Air Tags 页面骨架，`static/app.js` 管交互。提供审批卡片（能看穿子图内部的中断位置）、并行比价汇总、Store 偏好档案面板，`uvicorn web.app:app` 即可在浏览器里体验全部机制。

## 4. 核心高光代码赏析

### 4.1 结构化动态审批：先看清，再执行

在 `core/graph_builder.py` 中，开发者将每个子助理的工具分为了两拨：

```python
# 航班子助理的工具池被切分成两半
update_flight_safe_tools = [search_flights] # 安全工具：查询
update_flight_sensitive_tools = [update_ticket_to_new_flight, cancel_ticket] # 敏感工具：退改签

# 在图中添加两个不同的节点
builder.add_node("update_flight_safe_tools", create_tool_node_with_fallback(update_flight_safe_tools))
builder.add_node("update_flight_sensitive_tools", create_tool_node_with_fallback(update_flight_sensitive_tools))
```

真正的敏感 ToolNode 前面还有一个审批节点。它把全部调用打成 JSON 数据包交给 `interrupt()`；只有收到批准，才跳到真正的工具节点：

```python
def approval_gate(state: State) -> Command:
    calls = state["messages"][-1].tool_calls
    decision = interrupt({
        "kind": "tool_approval",
        "domain": "航班退改签",
        "tool_calls": [
            {"id": c["id"], "name": c["name"], "args": c.get("args", {})}
            for c in calls
        ],
    })
    if decision["approved"]:
        return Command(goto="update_flight_sensitive_tools")

    # 驳回时为每个 tool_call_id 补齐 ToolMessage，消息历史不会残缺
    return Command(
        update={"messages": [
            ToolMessage(
                tool_call_id=c["id"],
                content=f"用户拒绝：{decision['reason']}，请重新规划。",
            )
            for c in calls
        ]},
        goto="update_flight",
    )
```

批准与驳回都通过 `Command(resume=...)` 返回中断点。租车审批节点位于真子图内，父图仍能收到中断并展示完整路径。相比静态 `interrupt_before`，这里可以按金额或工具参数决定是否拦截，也能让前端直接渲染“将执行什么”。

### 4.2 对话状态压栈与弹栈

在 `core/state.py` 中，`dialog_state` 决定了当前是谁在跟用户对话：

```python
def update_dialog_stack(left: list[str], right: Optional[str]) -> list[str]:
    if right is None:
        return left
    if right == "pop":
        return left[:-1]  # 弹栈：子助理说“我搞定了，还给主助理”，状态回退
    return left + [right] # 压栈：主助理说“去机票部”，栈里多了一个 update_flight
```

## 5. 如何运行？

要亲自感受这个强大的系统，请进入代码目录 `code/travel_agent_v2/`（该目录自带 [README](code/travel_agent_v2/README.md)，含目录详解与模型切换说明）：

1. **安装依赖**（依赖清单见项目根目录的 `requirements.txt`）：
   ```bash
   pip install -r requirements.txt
   ```
2. **配置环境变量**（项目根目录提供了 `.env.example` 模板，复制为 `.env` 后填入你的 Key；`core/llm_config.py` 会在启动时自动加载它）：
   ```bash
   cp .env.example .env
   ```
   需要配置的核心变量：
   ```bash
   OPENAI_API_KEY="sk-xxxx"
   OPENAI_MODEL_NAME="gpt-4o-mini"          # 模型名与下面的服务地址必须配套！
   OPENAI_API_BASE="https://api.openai.com/v1"
   TAVILY_API_KEY="tvly-xxxx"               # 可选：主助理的全网搜索工具
   ```
   > ⚠️ **模型名与服务地址必须配套**：如果你想用 Claude / DeepSeek 等兼容 OpenAI 协议的模型，请同时修改 `OPENAI_MODEL_NAME` 和 `OPENAI_API_BASE`（`.env.example` 里给了三套可直接抄的方案）。给 OpenAI 官方地址配一个 `claude-*` 模型名是跑不通的。
3. **初始化数据库时间**：
   （为了防止提示词中的“明天”搜不到老数据库里的虚拟航班，脚本会自动平移数据库时间）
   代码启动时 `main.py` 会自动调用 `update_dates()` 函数刷新本地 SQLite 库。
4. **启动终端对话**（在 `travel_agent_v2/` 目录内运行）：
   ```bash
   python main.py
   ```

接下来，你就可以像使唤真实客服一样，开始刁难它吧！通过终端打印的绿色事件流，你能清晰地看到大模型是如何在不同的节点中穿梭、交接、并遇到敏感动作主动停下来向你请示的。

不想盯终端？跑 `uvicorn web.app:app`（在 `travel_agent_v2/` 目录内执行，Web 层要求 Python ≥ 3.13），在浏览器（http://127.0.0.1:7860）里用图形界面体验同样的机制：审批卡片会展示跨子图路径、待执行工具名和参数；并行比价结果以汇总卡片呈现；右侧是跨会话偏好档案。教学版仍使用进程内存储，启动命令不要加 `--workers N`。

## 6. 生产边界：为什么它还不是可直接上线的成品

这套代码演示了路由、子图、动态审批、长期记忆、并行和测试如何拼在一起，但生产环境还要补四道门：

1. **持久化**：把 `MemorySaver` / `InMemoryStore` 换成 Postgres 等持久化实现，并考虑备份、迁移、加密和数据保留周期；
2. **业务一致性**：SQLite 写操作要替换成正式业务 API，并加入幂等键、事务、审计与失败补偿，避免恢复或重试造成重复下单；
3. **安全与并发**：加入登录鉴权、租户隔离、会话归属校验、限流、异步 I/O、队列和水平扩容；
4. **质量保障**：除了假模型控制流测试，还要做真实模型轨迹评测、Prompt 注入测试、回归数据集、成本与延迟监控。

因此本文统一称它为“生产架构导向教学项目”：架构形状接近真实系统，依赖和运维仍刻意保持轻量。

> **小结：**
> 从早期的 LangChain Agent 一把梭，到今天的 LangGraph 1.x 意图流架构编排。我们看到 AI 编程正在走向真正的工程化。控制权不再完全听天由命地交给 LLM 去瞎猜，而是**由程序员设计好严谨的轨道图，大模型只负责在十字路口做路由判断**。这就是 Vibe Coding 时代的最佳 Agent 开发实践模式！
