# 05 图的可视化与流式调试

工作流一旦有了十几个节点、七八条边，光靠想象就很容易出错。幸运的是，LangGraph 内置了强大的**可视化**与**流式输出**能力，让你像看“实时地图”一样观察每一步的状态流转。

## 1. 把图“画”出来：四种可视化方式

编译后的图对象自带绘图方法。LangGraph 官方提供了多种可视化手段，按“要不要装额外依赖”分两档：

**第一档：零依赖，开箱即用**

```python
# 1. 打印 Mermaid 源码（复制到任意 Mermaid 在线编辑器即可查看）
print(app.get_graph().draw_mermaid())

# 2. 打印 ASCII 版图结构（需要 pip install grandalf，无需图形界面）
print(app.get_graph().print_ascii())
```

**第二档：渲染成图片**

```python
# 方式 A：导出 PNG（默认走 Mermaid Ink 在线 API，需要联网；也可改用本地 pyppeteer 渲染）
png = app.get_graph().draw_mermaid_png()
with open("my_graph.png", "wb") as f:
    f.write(png)

# 方式 B：基于 Graphviz 导出 PNG（需要先安装 graphviz，更适合精细复杂的图）
#   macOS: brew install graphviz
#   Debian/Ubuntu: sudo apt install graphviz
#   pip install pygraphviz
png2 = app.get_graph().draw_png()
with open("my_graph_graphviz.png", "wb") as f:
    f.write(png2)
```

> 💡 **装 Graphviz 的正确姿势**（社区教程里踩坑最多的点）：`draw_png()` 本质是调用系统里的 `dot` 命令。只装 Python 包 `pygraphviz` 是不行的，**必须先把 Graphviz 软件本身装好**（`brew install graphviz` 或 `apt install graphviz`）。报 `Program dot not found in path` 就是没装系统 Graphviz。如果只想快速看图，直接用零依赖的 `draw_mermaid()` 粘贴到 [mermaid.live](https://mermaid.live) 即可。

**生活化比喻：** 这就像把饭店的“动线图”贴在后厨墙上。厨师长（你）一眼就能看到：哪个菜该从哪个灶台出，谁连向谁，哪里可能堵车（死循环）。

## 2. 流式输出：看每个节点“实时表演”

`graph.invoke()` 会等全部跑完再返回结果，你只能看到“结局”。而 `graph.stream()` 会**逐步吐回每个节点产生的新状态**，让你看到过程：

```python
config = {"configurable": {"thread_id": "demo-1"}}
for event in graph.stream({"messages": [("user", "帮我查下周一的机票")]}, config):
    print(event)   # 每跑完一个节点，就打印一次它更新后的状态
```

```
{'planner': {'messages': [AIMessage(content='我需要先查询航班...')]}}
{'search_flights': {'messages': [ToolMessage(content='发现 3 个航班...')]}}
{'planner': {'messages': [AIMessage(content='为您找到以下航班...')]}}
```

每一行都是一个节点执行完毕后，“交接本”上新增的内容。这比黑盒的 `invoke` 好调试一百倍。异步场景（比如 FastAPI 接口里）用 `await graph.astream(...)` 即可，用法完全一致。

## 3. stream_mode：多种粒度的“监控探头”

`stream()` 支持 `stream_mode` 参数，决定你希望看到什么粒度的信息。官方支持的常见模式如下：

| stream_mode | 看到什么 | 适用场景 |
| :--- | :--- | :--- |
| `"updates"` | 每个节点**返回的增量更新**（只含新写的内容） | 聚焦“这个节点改了什么”，最常用 |
| `"values"` | 每个节点跑完后，**完整的**当前状态 | 想看到整个交接本的全貌 |
| `"messages"` | 逐 token 级别的 LLM 输出 `(token, 元数据)` 二元组 | 实现“打字机”式逐字输出 |
| `"custom"` | 节点里用 `get_stream_writer()` 主动写出的自定义数据 | 输出非消息类的中间进度 |
| `"checkpoints"` / `"debug"` / `"tasks"` | 检查点事件 / 底层调试信息 / 任务开始与结束 | 排查运行时底层问题 |

```python
# 消息级流式：像 ChatGPT 一样逐字输出
for msg_chunk, metadata in graph.stream(
    inputs, config, stream_mode="messages"
):
    print(msg_chunk.content, end="")
```

### 多个模式一起开 + v2 统一格式

LangGraph 1.1+ 支持传 `version="v2"`，让所有模式统一成 `{"type": ..., "ns": ..., "data": ...}` 的 `StreamPart` 结构，方便前端消费：

```python
for chunk in graph.stream(
    {"topic": "ice cream"},
    stream_mode=["updates", "custom"],
    version="v2",
):
    if chunk["type"] == "updates":
        for node_name, state in chunk["data"].items():
            print(f"节点 {node_name} 更新：{state}")
    elif chunk["type"] == "custom":
        print(f"进度：{chunk['data']}")
```

### 节点内主动上报进度（custom 模式）

如果一个节点要跑很久（比如批量调用），可以用 `get_stream_writer()` 主动上报中间进度：

```python
from langgraph.config import get_stream_writer

def heavy_node(state: State):
    writer = get_stream_writer()
    writer({"status": "正在查询第 1/10 家航司..."})
    # ... 做一些耗时的活 ...
    writer({"status": "正在查询第 2/10 家航司..."})
    return {"result": "done"}
```

## 4. 更细粒度：astream_events（token 事件流）

如果你要做的不是“按节点”而是“按事件”监控（比如监听 `on_chat_model_start` / `on_chat_model_stream` / `on_tool_start` / `on_tool_end`），用 `astream_events()`：

```python
async for ev in graph.astream_events(inputs, config, version="v2"):
    if ev["event"] == "on_chat_model_stream":
        print(ev["data"]["chunk"].content, end="")
```

> 💡 简单记：**`stream()` 的粒度是“节点”**（看每一步状态），**`astream_events()` 的粒度是“token/事件”**（看内部每一个细节，适合聊天 UI 逐字渲染）。做前端实时聊天用后者，做流程调试用前者。

## 5. 调试三板斧：可视 + 流式 + 日志

遇到“图跑得不对”时，按下面顺序排查：

1. **画图**：`print(app.get_graph().draw_mermaid())`，确认节点与边的连接符合预期；
2. **流式观察**：`graph.stream(..., stream_mode="updates")`，逐节点确认数据有没有按预期流转；
3. **节点内打日志**：在每个节点函数里 `print(f"进入节点：{...}")`，确认每个节点收到了正确的输入。

```python
def query_flights(destination: str) -> list:
    """模拟航班查询：真实项目里换成真实的查询函数"""
    return [f"{destination} 航班 CA-{1800 + len(destination) * 7}"]

def search_flights_node(state: State):
    print(">>> 进入 search_flights，收到输入：", state.get("destination"))
    result = query_flights(state["destination"])
    print(">>> search_flights 返回：", result)
    return {"flight_results": result}
```

> 🩺 **小进阶**：如果图里嵌了子图，可视化时传 `xray=True` 可以“透视”到子图内部：`app.get_graph(xray=True).draw_mermaid()`。生产环境还有 LangSmith、Langfuse 这类全链路追踪平台（本知识库暂不引入，取舍理由见 15 节），但无论用不用它们，本节的“三板斧”都是最基础的观测手段。

## 6. 小试牛刀：给 02 节的图加上可视化

把 02 节的“assistant -> END”小图升级一下，加上调试能力：

```python
from langgraph.graph import StateGraph, START, END

builder = StateGraph(State)
builder.add_node("assistant", agent_node)
builder.add_edge(START, "assistant")
builder.add_edge("assistant", END)

app = builder.compile()

# 1. 可视化
print(app.get_graph().draw_mermaid())

# 2. 流式运行
for event in app.stream({"messages": [("user", "你好！")]}):
    print("----- 事件 -----")
    print(event)
```

看到输出里每个节点对应的 key（这里是 `assistant`），就说明你已经掌握了 LangGraph 调试的基本功。
