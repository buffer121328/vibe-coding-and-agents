# Product

## Platform

web

## Users

两类人在用这台工作台：

1. **读者 / 学员**（主要）：跟着第 10 章《LangGraph 搭建工作流》边读边在本机跑这份代码的人。他在自己电脑上开着 `127.0.0.1:7860`，一边对话一边要看清楚「图走到哪个节点了、审批闸门为什么挂住、库存被谁改了」——界面是这套多智能体机制的可视化教具。
2. **运营角色**（`role=ops`，演示用）：要看全量订单与审计流水，用来讲清「界面藏按钮不等于权限」。

使用者处在「边学边点」的场景：桌面上开着编辑器、终端和浏览器，看屏幕的时间长，读的是状态与数字，不是营销文案。

## Product Purpose

一个基于 LangGraph 1.x 的国内旅行助手整机：主助理负责分诊，四个专员（机票 / 酒店 / 租车 / 景点门票）各管一摊，所有写操作在执行前都要过一次人工审批（`interrupt()`）。

界面要同时把两件事说清楚：

- **对旅客**：查攻略、比价、下单、退单、记住偏好——能靠对话办，也能不靠对话直接翻库存。
- **对学习者**：把「智能体在干什么」摊开——当前节点、对话状态栈、节点时间线、挂起的审批里到底打包了什么。

## Positioning

同类教学 Demo 通常停在「聊天框 + 一坨 JSON」。这台工作台的差别在于**把工具回执变成了界面结构**：工具返回的库存长成卡片，库存状态长成一块出发信息看板，审批挂起长成一张可签字的单据。界面不是贴上去的一层皮，而是这套多智能体机制的另一半解释。

## Operating Context

- 本机运行：`uvicorn web.app:app`（单 worker，`127.0.0.1:7860`）。改 `static/app.js` 或页面 CSS 必须重启才生效（Air 的 HashedStatic 会给脚本换内容哈希名）。
- 数据分两处：业务库 `db/travel_new.sqlite`（机场 / 航班 / 酒店 / 租车 / 门票，每次启动从种子库重建）；应用库 `db/app.sqlite`（账号 / 会话目录 / 订单 / 审计，**不参与重建**）。
- 服务在跑的时候不要删 `db/app.sqlite`。
- 内容定位是国内：国内机场（PEK/CTU/SYX/XIY…）、国内航司与酒店租车品牌、国内景点玩法。城市在库里存英文、界面显示中文。
- 全离线可跑：不引 npm 构建链；图片素材本地存放（Wikimedia 自由授权，署名见 `static/img/CREDITS.md`）。

## Capabilities and Constraints

已确认存在的功能（界面必须都能到达）：登录 / 注册（图形验证码；邮箱验证码暂时下线，见登录页说明）、对话（工具过程可折叠、正文流式）、行程（真实底图上按航段平铺）、生成式结果卡片、按城市翻库存（不经过模型）、库存看板、订单（下单 / 退单）、审计流水（ops）、会话历史（新建 / 切换 / 改名 / 删除）、偏好档案（Store）、节点时间线、审批闸门（批准 / 驳回）。

约束：

- 页面由 Python 侧 `web/present/views.py` 生成骨架（Air Tags），**全部交互在 `static/app.js`**，无框架、无构建步骤。
- 前端与后端的契约是 DOM id 与 `data-*` 属性（`data-prompt` / `data-url`），改名要同时改测试。
- 测试断言页面元素存在（`tests/test_web_api.py::test_page_renders`），界面改版要同步断言。
- 中文界面的控件一律用通行叫法：登录 / 注册 / 退出登录 / 对话 / 行程 / 探索 / 看板 / 订单 / 运维，不把比喻延伸到控件上。

## Evidence on Hand

- 真实数据：国内机场与航段（四份演示档案：alice 北京↔成都、bob 上海↔三亚、carol 广州↔西安、ops 杭州↔青岛）、酒店 / 租车 / 门票库存、真实底图 `static/img/map/china.svg`、16 个城市的实景照片。
- 真实机制：`db/checkpoints.sqlite` 里的对话存档、`interrupt()` 的审批数据包、Store 里的跨会话偏好。
- 没有的东西（不能编）：真实成交价、真实用户评价、真实运营指标。

## Product Principles

1. **状态优先于文案**：把机器在干什么画出来（节点、栈、闸门、库存），少写解释性长句。
2. **一页一件事**：每块内容有自己的位置，不把七件事挤进一屏三栏。
3. **浏览与对话并列**：不靠模型也能翻库存、看订单、查行程。
4. **数字要对齐**：时间、编号、金额、数量一律等宽数字对列——可信感来自对齐。
5. **教学透明**：挂起的审批、状态栈、时间线都能被看见，不藏在日志里。
