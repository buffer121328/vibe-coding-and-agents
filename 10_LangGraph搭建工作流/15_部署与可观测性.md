# 15 部署与可观测性：让 Agent 上线并看得见

前面十五节，你的图都在终端里跑。要变成真正给用户用的产品，还差两件事：**部署**（让图变成一个稳定的 API 服务）和**可观测性**（生产环境出了问题，你能看见它卡在哪一步、花了多少钱、答得对不对）。

## 1. 部署：把图变成服务

**生活化比喻：** 你家后厨（本地脚本）菜做得再好，顾客也吃不到。部署就是把后厨搬进临街店面（服务端）：装修标准化（统一 API）、门口挂菜单（接口文档）、请收银员（鉴权与队列）。

LangGraph 官方的部署工具链分三层，由轻到重：

| 方案 | 是什么 | 适合 |
| :--- | :--- | :--- |
| **本地 Server** | `langgraph dev` / `langgraph up`，一条命令把图变成带 REST API 的本地服务 | 开发自测、联调 |
| **Agent Chat UI** | 官方开源的聊天前端模板，接上 Server 就有对话框 + 中断审批 UI | 快速做个演示站点 |
| **LangGraph Platform** | 官方托管平台：自动扩缩容、持久化任务队列、定时任务（Cron）、流式推送 | 生产上线，不想自己运维 |

本地跑服务的关键是一个 `langgraph.json` 配置文件——声明你的图在哪、依赖是什么：

```json
{
  "dependencies": ["."],
  "graphs": {
    "travel_agent": "./travel_agent_v2/main.py:graph"
  },
  "env": ".env"
}
```

然后 `langgraph dev`，图就从“终端程序”升级成了带 API、自带 Studio 调试界面的服务。16 节旅行助手里的 `interrupt_before` 审批环节，在部署后自动变成前端可处理的 API 中断事件——你在终端里输 `y` 的那一步，在 Web UI 里就是一个“批准”按钮。

## 2. 可观测性：给 Agent 装监控大屏

Agent 生产化的真正难点不是“跑不起来”，而是“跑歪了你不知道”：某天回答质量下滑，是 Prompt 问题？模型抽风？还是检索工具返回了垃圾？全链路追踪就是为此而生的。

**生活化比喻：** Agent 的执行像外卖配送：下单（用户提问）→ 商家接单（模型思考）→ 骑手取餐（工具调用）→ 送达（最终回答）。LangSmith 这类追踪平台就是这张订单的**全程物流追踪页**——每一环几点几分发生、耗时多少、中间的“包裹内容”（Prompt 与响应全文）都可点开查看。

### 本知识库的取舍：暂不引入 LangSmith / Langfuse 等观测框架

市面上主流的观测框架有 LangChain 官方的 [LangSmith](https://smith.langchain.com/) 和开源的 [Langfuse](https://github.com/langfuse/langfuse) 等，它们能把每一次执行的完整链路（每个节点、每次模型调用、每次工具执行）记录成可检索的追踪页，并支持指标统计与评测回归。但**本章以及本知识库的所有项目暂不接入它们**，统一用 05 节的“调试三板斧”（可视化 + 流式 + 打日志）做观测。理由有三：

1. **零依赖可运行**：接入观测平台通常要注册账号、申请 Key、连云端服务（Langfuse 私有化部署也至少要多运维一个服务），而本知识库的所有示例都应做到“装好 langgraph 就能跑”；
2. **数据不出域**：追踪会把完整的 Prompt、响应、工具返回值上传到第三方（或自建服务器），教学演示没必要为此引入隐私与合规顾虑；
3. **不是知识缺口**：观测框架是“装上去就能用”的工具，不是需要专门训练的能力；先把日志与流式调试的基本功练扎实，将来团队需要时再接入不迟。

> 💡 **本库的实际做法**：在 05 节“可视 + 流式 + 打日志”三板斧之上，本章各节的示例都用 `stream_mode="updates"` 逐节点打印状态、在节点函数里留 `print` 日志——不依赖任何外部平台，也能看到每一步“谁改了什么”。等将来接入观测平台时，这套路日志恰好就是最合适的埋点位置。

> 🔧 **动手建议**：下一节的综合实战项目自带一个现成的 `graph` 对象——学完本节后，不妨给它配一个 `langgraph.json` 用 `langgraph dev` 跑起来，在终端流式输出里观察多智能体的接力过程，你会对“可观测”三个字有体感。
