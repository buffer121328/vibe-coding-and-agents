# 8.12 可观测性与性能评估：给 Agent 装上仪表盘与体检报告

> **“赛车手没有仪表盘，就看不出转速与油耗，也就不可能调校出冠军圈速——Agent 也一样：没有可观测性，你永远只能靠猜来优化它。”**

***

## 🕵️ 黑盒 Agent 的三大困惑：为什么必须可观测？

经过 8.1 - 8.10 的逐个攻坚，我们已把 Agent 的每个器官都搓好了；8.11 的会话持久化让它学会了存档，8.13 的综合实战将把所有器官组装成完整的个人助手。而在正式组装之前，我们先给它装上一套"仪表盘"——否则一旦跑起来，它几乎是一个**黑盒**：

1. **它到底在干嘛？** —— 任务卡住了，它是在思考、在等工具返回、还是陷入了死循环？你只能干瞪眼；
2. **花了多少钱？** —— 跑了十分钟，Token 烧了多少？账单上的钱花得值不值？
3. **跑得多快？** —— 平均一步多久？哪个工具调用最慢？哪里是性能瓶颈？

如果这些问题答不上来，任何“优化”都只是拍脑袋。这正是**可观测性（Observability）**要解决的命题。工业界为此沉淀了两条关键经验，本节我们逐一复刻：

| 经验来源 | 核心思想 | 我们本节实现 |
| :--- | :--- | :--- |
| [hello-agents](https://github.com/datawhalechina/hello-agents) 第12章「智能体性能评估」 | 定义评估指标、跑基准测试、用评估框架量化 Agent 质量 | `EvalSuite` 评估套件：成功率 / 平均耗时 / 平均 Token |
| [Pi (earendil-works/pi)](https://github.com/earendil-works/pi) 的「事件驱动」设计 | 事件联合体 + `subscribe` 订阅机制，让外部实时感知 Agent 全过程 | `EventBus` 事件总线 + `AgentEvent` 事件联合体 + `TokenCostAudit` 费用审计 |

***

## ⚡ 事件驱动 vs 事后打印：从“马后炮”到“实时直播”

最朴素的可观测方式是**事后打印**：在 Agent 每个关键节点 `print` 一行日志。它能工作，但毛病不少：

- **耦合**：日志逻辑硬编码在 Agent 主流程里，加一个“费用统计”就要改 Agent 源码；
- **无结构**：打印出的是一堆字符串，无法被程序化消费（统计、过滤、回放）；
- **不可旁观**：外部模块（Web UI、监控面板）无法在运行中实时订阅到内部状态。

**事件驱动（Event-Driven）**则彻底换了一种姿势：Agent 不关心谁在看，它只负责把每一次动作“广播”成一条**事件**；任何关心者都可以通过 `subscribe` 订阅。这正是 Pi 项目的核心设计——事件联合体 + 订阅发布。

## 💻 源码实现：给 Agent 装上仪表盘与体检报告

完整代码见 `code/s12_observability.py`，共 4 个核心组件。

### 1️⃣ AgentEvent：可观测事件联合体

Pi 项目用“事件联合体”描述一切运行时动作。我们用 `@dataclass` 实现一个轻量版：**事件类型 + 工具名 + 内容 + Token + 耗时 + 时间戳**，再提供 `to_dict()` 便于 JSON 化：

```python
@dataclass
class AgentEvent:
    """🚀 一条可观测事件（Pi 风格事件联合体）：记录 Agent 运行中的一次瞬时动作"""
    event_type: str      # agent_start / llm_call / tool_call / tool_result / compact / error / finish
    tool_name: str = ""  # 涉及的工具名（非工具事件为空）
    content: str = ""    # 事件附带文本（工具结果 / 回复 / 错误信息）
    tokens: int = 0      # 本次 LLM 调用消耗的总 token 数
    latency_ms: float = 0.0   # 本次动作耗时（毫秒）
    timestamp: float = field(default_factory=time.time)  # 事件发生时间戳

    def to_dict(self) -> Dict[str, Any]:
        """将事件序列化为字典，便于 JSON 展示与持久化"""
        return {"event_type": self.event_type, "tool_name": self.tool_name, "content": self.content,
                "tokens": self.tokens, "latency_ms": round(self.latency_ms, 2), "timestamp": round(self.timestamp, 3)}
```

`event_type` 枚举了 Agent 的**完整生命周期**：任务启动 → LLM 调用 → 工具执行 → 工具结果 → （上下文压缩）→ 错误 → 完成。这 7 种事件足以描述 Agent 的每一个关键时刻。

### 2️⃣ EventBus：Pi 风格的事件总线（subscribe / emit）

事件总线是订阅发布的调度中枢：`subscribe` 注册监听器，`emit` 广播事件。我们额外支持 **`'*'` 通配订阅**（Pi 风格），让关心“一切”的观察者（比如费用审计、轨迹回放）一次订阅即可收到所有事件；同时用 `self.history` 保留**完整事件历史**，方便事后审计与回放：

```python
class EventBus:
    """📡 事件总线：让外部模块实时感知 Agent 的完整运行过程"""
    def __init__(self) -> None:
        self._subscribers: Dict[str, List[Callable[[AgentEvent], None]]] = {}
        self.history: List[AgentEvent] = []   # 📼 完整事件历史（审计 / 回放用）

    def subscribe(self, event_type: str, callback: Callable[[AgentEvent], None]) -> None:
        """订阅某类事件；传 '*' 表示通配订阅所有事件（Pi 风格）"""
        self._subscribers.setdefault(event_type, []).append(callback)

    def emit(self, event: AgentEvent) -> None:
        """广播一条事件：分发给精确匹配者 + 通配订阅者，并写入历史"""
        self.history.append(event)
        for cb in list(self._subscribers.get(event.event_type, [])) + self._subscribers.get("*", []):
            cb(event)
```

> 💡 **设计亮点**：Agent 主流程从此只需要关心“我发生了什么”，而“谁关心、关心什么”全部由外部订阅者决定——这就是**关注点分离**。

### 3️⃣ TokenCostAudit：tiktoken 费用审计员

费用审计用 `tiktoken` 估算文本 Token 数（中文友好编码器 `cl100k_base`），内置一张**简易定价表**（教学用假想价格，真实价格请以 GLM 官方为准），每次 `record_usage` 累计成本与耗时，`summary()` 输出人类可读账单：

```python
class TokenCostAudit:
    """💰 费用审计员：用 tiktoken 估算 token，并按定价表换算人民币账单"""
    # 💡 简易定价表（元 / 每百万 token）—— 教学用假想价格，真实价格以 GLM 官方为准
    PRICES = {"deepseek-v3": {"input": 2.0, "output": 8.0},   # 输入 2 元 / 输出 8 元（假想）
              "deepseek-r1": {"input": 4.0, "output": 16.0}}  # 输入 4 元 / 输出 16 元（假想）；均为教学假想价，真实以官方为准

    def record_usage(self, model_name: str, input_tokens: int, output_tokens: int,
                     latency_ms: float = 0.0) -> None:
        """记录一次 LLM 调用用量：输入/输出 token 与耗时，并累计成本"""
        price = self.PRICES.get(model_name, self.PRICES["deepseek-v3"])
        cost = (input_tokens / 1e6) * price["input"] + (output_tokens / 1e6) * price["output"]
        self._records.append({"model": model_name, "input_tokens": input_tokens, "output_tokens": output_tokens,
                              "cost": cost, "latency_ms": latency_ms})
```

`summary()` 则把累计统计整理成**人类可读的账单文本**，直接打印或喂给 UI：

```python
    def summary(self) -> str:
        """输出人类可读的费用审计账单文本"""
        n = len(self._records)
        recs = self._records
        total_in = sum(r["input_tokens"] for r in recs); total_out = sum(r["output_tokens"] for r in recs)
        cost = sum(r["cost"] for r in recs); avg = sum(r["latency_ms"] for r in recs) / n if n else 0.0
        return (f"📊 ====== Token 费用审计账单 ======\n"
                f"🔢 调用次数      : {n}\n"
                f"📥 输入 Tokens   : {total_in:,}\n"
                f"📤 输出 Tokens   : {total_out:,}\n"
                f"🧮 总 Tokens     : {total_in + total_out:,}\n"
                f"💴 预估成本      : ¥ {cost:.4f}\n"
                f"⏱️ 平均时延      : {avg:.1f} ms")
```

这里 `input_tokens` 与 `output_tokens` 从哪里来？通常由 Agent 在每次 LLM 调用后回填：输入侧估算 `prompt` 的 Token，输出侧对模型回复文本用 `tiktoken` 精确估算，二者之差即输入 Token——我们把它封装成 `_on_llm_call` 监听器挂在 EventBus 上，**订阅 `llm_call` 事件即可被动记账**，完全不用侵入 Agent 主循环。

### 4️⃣ EvalSuite：评估套件（hello-agents 第12章思想）

`EvalSuite` 把“评估”做成一个严肃的流程（参考 [hello-agents](https://github.com/datawhalechina/hello-agents) 第12章）：对**一组任务**各跑 `trials` 次，每次用**独立的 EventBus** 收集轨迹，最后用关键词匹配判断成功与否，汇总出**成功率 / 平均耗时 / 平均 Token**：

```python
class EvalSuite:
    """🎯 评估套件：对一组任务各跑 trials 次，统计成功率 / 平均耗时 / 平均 token"""
    def __init__(self, client, tasks: List[str], trials: int = 3, ...):
        self.client = client          # 兼容 ZhipuGLMClient（真实评估时使用）
        self.tasks, self.trials = tasks, trials
        self.success_keywords = success_keywords or ["成功", "完成", "✅", "OK"]
        self.fail_keywords = fail_keywords or ["失败", "错误", "异常", "❌"]
        self.audit = TokenCostAudit()

    def _is_success(self, output: str) -> bool:
        """用关键词子串匹配判断成功：先看失败词，再看成功词"""
        return not any(k in output for k in self.fail_keywords) \
            and any(k in output for k in self.success_keywords)

    def run_eval(self, agent_runner_callable: Callable[[EventBus, str], str]) -> Dict[str, Any]:
        self.audit = TokenCostAudit()
        report: Dict[str, Any] = {"summary": {}, "tasks": {}}
        for task in self.tasks:
            s_ok, lats, toks, trs = 0, [], [], []
            for _ in range(self.trials):
                bus = EventBus()
                bus.subscribe("llm_call", self._on_llm_call)      # 🪝 挂载费用审计监听
                t0 = time.perf_counter()
                out = agent_runner_callable(bus, task)            # 🏃 运行一次 Agent
                lat = (time.perf_counter() - t0) * 1000           # ⏱️ 统计总耗时
                lats.append(lat)
                toks.append(sum(e.tokens for e in bus.history))   # 🧮 累加本次运行的 token
                ok = self._is_success(out); s_ok += ok
                trs.append({"output": out, "success": ok,
                            "events": [e.to_dict() for e in bus.history]})
            report["tasks"][task] = {"success_rate": round(s_ok / self.trials, 3),
                                     "avg_latency_ms": round(sum(lats) / self.trials, 1),
                                     "avg_tokens": round(sum(toks) / self.trials, 1), "traces": trs}
        return report
```

> 💡 **关键理解**：`run_eval` 接受一个 **`agent_runner_callable(bus, task)`** —— 你的 Agent 被包装成“接收事件总线、执行任务、返回最终文本”的函数。评估套件完全不关心 Agent 内部实现，只要它愿意 `emit` 事件即可被统计。这正体现了事件驱动的**开闭原则**。

### 🧭 契约：如何把任意 Agent 包装成可评估的 runner？

评估套件对 runner 只有一条要求：**签名为 `(bus, task) -> str`**，并在关键节点主动 `emit` 事件。以 8.13 收官章节的 `MiniAgent`（`code/s13_mini_agent.py`）为例，只需在它的主循环里插入几行"广播"即可无缝接入：

```python
def agent_runner(bus: EventBus, task: str) -> str:
    """🧭 把任意 Agent 包装成 (bus, task) -> 最终文本 的可评估函数"""
    audit = TokenCostAudit()
    bus.emit(AgentEvent("agent_start", content=f"🎬 开始任务：{task}"))
    reply = your_agent.run(task)                      # 🏃 你的 Agent 主循环（跑完并返回最终答复）
    bus.emit(AgentEvent("llm_call", content=reply,
                        tokens=audit.estimate_tokens(reply), latency_ms=random.uniform(300, 900)))
    if "失败" in reply:                               # 出错时额外广播 error 事件
        bus.emit(AgentEvent("error", content="捕获到模型报错，正在记录。"))
    bus.emit(AgentEvent("finish", content=reply))
    return reply
```

接入成本极低：**Agent 主流程几乎不改，只多几行 `emit`**；而费用统计、轨迹回放、成功率计算这些“体检项目”全部由订阅者完成。

## 📝 本节小结

- **事件驱动是可观测性的基石**：Agent 只负责 `emit`，外部用 `subscribe` 各取所需（参考 Pi 的事件驱动订阅机制），彻底解耦日志与主流程；
- **费用审计让成本透明**：`tiktoken` 估算 + 定价表换算，每跑一次任务都能拿到“人民币账单”，钱花在哪看得明明白白；
- **评估套件让优化有据可依**：参考 hello-agents 第12章，用成功率 / 平均耗时 / 平均 Token 三个指标量化 Agent 质量——没有体检报告，就谈不上“性能优化”；
