#### 1. 原因 A：模型开启了「🧠 深度思考」或正在执行「多步工具调用/子代理协作」
- **排查依据**：
  - 在 `8.13 个人 Mini-Agent` 中勾选了 **“🧠 深度思考”**；
  - 或者是运行 `8.10 Subagents 多智能体`（4 个专家串行流转）或 `8.2 ReAct 循环`（多步反复搜索）。
- **底层原理**：
  - 深度思考模型（如 GLM / DeepSeek 推理模式）会在输出答案前生成数千 Token 的隐式思维链（Chain-of-Thought），在大脑内部推演规划，耗时通常在 **10~30 秒**；
  - 同样，Subagents 需要依次调用“搜索专家 ➔ 代码专家 ➔ 评测专家 ➔ 总结主厨”，总用时等于 4 次 LLM 调用的总和。
- **解决方案**：
  - 展开右侧底部的 **“🔍 决策流与权限门禁审计 Trace”** 折叠面板，观察 Agent 当前处于哪一步；
  - 调试阶段若追求极速响应，可在 8.13 界面中**取消勾选“🧠 深度思考”**，切换为极速直出模式。

#### 2. 原因 B：触发了权限安全门禁（HITL），后台终端正在等待人类审批 `[y/N]`
- **排查依据**：
  - 运行了 `s06_permissions_hitl.py`、`s05_terminal_and_edit.py`，或在 Agent 中触发了高危指令（如修改系统文件、执行终端命令）；
  - 网页界面一直在转圈，没有任何报错。
- **底层原理**：
  - 在第 8.6 节中，我们手搓了 `PermissionGuard` 风险门禁。当遇到中高风险操作（如 `str_replace` 修改代码、执行未在白名单的 Bash 命令）时，代码会调用原生 `input("⚠️ 是否允许执行？[y/N]: ")` 阻塞主线程，等待人类审批。
- **解决方案**：
  - **切回到你的命令行终端窗口**，查看是否有黄色拦截提示；
  - 在终端中输入 `y` 并按回车，Agent 会立即解除挂起，继续向前执行。

#### 3. 原因 C：本地开启了全局科学上网代理 (VPN / Clash)，导致国内 API 网关被绕路或阻断
- **排查依据**：
  - 终端运行脚本报错 `ConnectTimeout`、`ReadTimeout`、`SSLError`，或没有任何输出长达 60 秒后抛出 `APIConnectionError`。
- **底层原理**：
  - 智谱 BigModel API（`open.bigmodel.cn`）服务器部署在中国大陆国内机房。如果你的电脑开启了全局科学上网代理（Global Proxy），请求会被强制绕道境外节点再尝试访问国内，极易触发网络握手超时、证书阻断或直接被节点拒接。
- **解决方案**：
  - **测试连通性**：在终端执行：
    ```bash
    curl -I https://open.bigmodel.cn/api/paas/v4/chat/completions
    ```
    若返回 `HTTP/1.1 401 Unauthorized` 或 `405 Method Not Allowed` 即代表网络通畅；若一直无响应卡住，则证明被代理阻断。
  - **代理设置规则**：将代理软件切换为 **“规则模式 (Rule)”**，并将 `*.bigmodel.cn`、`*.volces.com` 加入**DIRECT 直连白名单**。

#### 4. 原因 D：API Key 欠费、未生效或单秒请求超限 (RateLimit 429)
- **排查依据**：
  - 控制台输出包含 `429 Too Many Requests` 或 `Insufficient Balance`。
- **解决方案**：
  - 登录 [智谱 BigModel 开放平台控制台](https://open.bigmodel.cn/)，检查账户余额与实名认证状态；
  - 在 `.env` 中配置备用灾备 Key（如火山方舟 `ARK_API_KEY`），`ZhipuGLMClient` 会在主力接口异常时自动无缝降级。

#### 5. 原因 E：极速验证最小连通性脚本
当你搞不清楚到底卡在哪一步时，**不要先跑复杂的 Web 工作台**，先跑 8.1 的 10 行最小原生测试：
```bash
cd 08_手搓Agent/code
uv run python s01_env_setup.py
```
- 如果 1 秒内能看到终端彩色打字机逐字吐出 Token，说明**模型与网络基建 100% 正常**，问题仅在具体交互逻辑或输入参数上。

#### 1. 核心原因 1：浏览器缩放比例过大或屏幕物理分辨率有限
- **根因说明**：
  - `app.py` 内部采用了高沉浸感的 `gr.Row()` 响应式三栏布局（`Sidebar: 2` + `CodeViewer: 5` + `Playground: 5`），并设置了固定对齐高度 `height: 740px`。
  - 当屏幕宽度低于 `1280px`（或系统开启了 125%/150% 缩放导致逻辑像素不足）时，CSS 布局会自动触发保底流式换行，导致界面看起来挤压重叠。
- **🚀 1 秒恢复完美视效**：
  - **缩放浏览器**：在浏览器页面中按下 **`Cmd + -` (Mac)** 或 **`Ctrl + -` (Windows)**，将页面缩放调整为 **80% ~ 90%**；
  - **窗口最大化**：双击浏览器顶部标题栏全屏放大窗口；
  - 按下 **`Cmd + 0` / `Ctrl + 0`** 可随时恢复默认 100% 比例。

#### 2. 核心原因 2：第三方暗黑模式扩展（如 Dark Reader）色彩冲突
- **根因说明**：
  - 工作台的源码视窗采用了标准的 **Pygments OneDark 极客黑配色**，而右侧沙箱卡片采用了**明晰高对比度的浅色卡片**。
  - 如果浏览器安装了 `Dark Reader`、`Super Dark Mode` 等插件，插件会强行反转所有颜色，把深色背景的代码文字也反色为深灰色，导致“黑底黑字”或“白底白字”无法看清。
- **解决方案**：
  - 点击浏览器右上角扩展栏的 `Dark Reader` 图标；
  - 点击开关，将 `http://127.0.0.1:7860` 或 `localhost` 加入**禁用名单 (Disable for this site)**。

#### 3. 核心原因 3：浏览器缓存了旧版本 CSS 样式
- **解决方案**：
  - 强制清除缓存硬刷新：
    - **Mac 用户**：按下 `Cmd + Shift + R`；
    - **Windows / Linux 用户**：按下 `Ctrl + F5`。

#### 4. 🛠️ 进阶：小屏轻薄本适配（自定义 CSS 响应式微调）
如果你日常使用的是 13 寸轻薄本，希望页面更紧凑，可以直接在 `app.py` 中微调两处参数：
1. **调小视窗固定高度**：将 `custom_css` 中的 `height: 740px` 调整为 `height: 620px`；
2. **调整导航栏宽度**：将 `Column(scale=2, min_width=200)` 中的 `min_width=200` 调整为 `min_width=160`。

## 🛠️ 专题三：环境依赖与 Python 解释器常见报错

### 1. 报错 `ModuleNotFoundError: No module named 'openai'` / `'gradio'` / `'rich'`

```bash
# ❌ 错误现场：
Traceback (most recent call last):
  File "app.py", line 19, in <module>
    import gradio as gr
ModuleNotFoundError: No module named 'gradio'
```

- **根因**：直接使用了操作系统全局的 Python（如系统自带的 Python 3.9/3.10），而没有进入由 `uv` 管理的 `.venv` 虚拟环境。
- **正解（二选一）**：
  - **方案 1（极力推荐）**：使用 `uv run` 免手动激活虚拟环境：
    ```bash
    cd 08_手搓Agent/code
    uv sync                   # 安装全部依赖到 .venv
    uv run python app.py      # 由 uv 自动加载 .venv 环境
    ```
  - **方案 2（传统手动激活）**：
    ```bash
    # macOS / Linux
    source .venv/bin/activate
    python app.py

    # Windows PowerShell
    .venv\Scripts\Activate.ps1
    python app.py
    ```

---

### 2. VS Code / Trae 编辑器中代码整页黄色波浪线标红

- **根因**：IDE 默认将解释器关联到了系统全局 Python，未能识别到 `08_手搓Agent/code/.venv`。
- **一秒修复**：
  1. 在编辑器中按下快捷键 `Cmd + Shift + P` (Mac) 或 `Ctrl + Shift + P` (Win) 打开命令面板；
  2. 搜索并点击 **`Python: Select Interpreter` (选择解释器)**；
  3. 选择 `./.venv/bin/python`（或点击“输入解释器路径”浏览选中 `08_手搓Agent/code/.venv/bin/python`）；
  4. 瞬间所有模块标红与警告全部消失！

## 💻 专题五：终端执行 (8.5) 与权限门禁 (8.6) 跨平台疑难

### 1. Windows 环境下运行 `s05_terminal_and_edit.py` 提示 `FileNotFoundError: 'ls' is not recognized`
- **根因**：`run_bash` 模块底层默认调用了 POSIX 标准终端命令（如 `ls`、`pwd`、`cat`、`grep`）。Windows 系统默认命令解释器为 `cmd.exe` 或 `PowerShell`，命令语法与 Linux 存在差异。
- **解决方案**：
  - **推荐方式**：在 Windows 终端（Windows Terminal）中使用 **Git Bash** 或 **WSL2 (Ubuntu)** 运行代码；
  - **原生 PowerShell 替代**：在 Windows 原生环境中，可将测试 Prompt 中的 `ls -la` 替换为 `dir` 或 `Get-ChildItem`。

---

### 2. 精准行替换 `str_replace` 报错：“未找到精确匹配的代码行”
- **根因**：
  - `str_replace` 是借鉴 Claude Code 的精密手术刀式代码编辑工具，要求 `old_str` 必须与目标文件中的内容 **100% 严格一致（包括每一处空格缩进与换行符）**；
  - Windows 环境换行符为 `\r\n` (CRLF)，而 macOS / Linux 为 `\n` (LF)，跨平台剪切板复制时可能会混入不可见换行符。
- **解决方案**：
  - 确保编辑代码前，先通过 `view_file` 读取目标文件的真实内容并带行号对照；
  - 在 `s05_terminal_and_edit.py` 的实现中，我们已加入了 `.replace('\r\n', '\n')` 自动归一化清洗逻辑。

## 🗜️ 专题六：上下文压缩 (8.8) 与记忆持久化 (8.9) 常见疑难

### 1. 为什么在 8.8 工作台中点击“压缩”后，Token 数量没有变化？
- **根因**：
  - 在 `s08_context_compact.py` 中，我们设计了防抖阈值保护。如果当前对话历史的总 Token 数尚未超过设定的安全阈值（例如低于 1000 Token），系统判定无需浪费算力进行压缩，会直接跳过。
- **体验方法**：
  - 在 8.8 工作台中点击预设按钮 **“📦 注入超长对话测试用例 (模拟 20 轮代码调试)”**；
  - 注入后消息达到 3000+ Token，此时点击 **“🗜️ 触发 /compact 深度提炼”**，即可瞬间看到 Token 从 3000+ 骤降至 300~500，且关键上下文无损保留。

---

### 2. 长期记忆文件 `gradio_agent_memory.json` 报错或数据混乱如何重置？
- **根因**：多次并发调试或手动修改 JSON 文件导致格式损坏（JSONDecodeError）。
- **一秒重置**：
  - 直接删除该本地文件即可，系统在下一次对话时会自动重新初始化：
    ```bash
    rm -f gradio_agent_memory.json
    ```

## 👥 专题七：Subagents 协作 (8.10) 与 Mini-Agent (8.13) 进阶疑难

### 1. Subagents 多智能体流水线执行耗时较长（约 20~40 秒）
- **现象分析**：
  - 在 8.10 演示中，`DeepResearchPipeline` 会依次调度 **4 个具备完全独立上下文的专家智能体**：
    1. 🔍 检索专家 (Searcher) ➔ 抓取最新资讯与数据；
    2. 💻 代码专家 (Coder) ➔ 编写并验证原型代码；
    3. ⚖️ 审校专家 (Critic) ➔ 审查代码质量与安全性；
    4. ✍️ 报告主厨 (Synthesizer) ➔ 综合提炼为全景技术报告。
  - 由于每个专家都有独立的 Prompt 与思考推理过程，单次完整流水线会发起 4 次连续的 LLM 调用，耗时 20~40 秒属于**完全正常的工业级推演开销**。

---

### 2. DuckDuckGo 免费联网搜索超时或返回空列表
- **根因**：
  - 本项目教学代码为了让大家**零门槛开箱即用、无需付费购买任何第三方搜索 API Key**，内置了基于 DuckDuckGo HTML 的免 Key 轻量抓取机制；
  - 当本地网络访问 DuckDuckGo 不稳定或触发其反爬频控时，可能返回空列表。
- **降级容灾设计**：
  - 在 `s13_mini_agent.py` 中，我们为联网搜索内置了**智能兜底机制**：当网络搜索失败时，Agent 会自动降级为“基于自身训练知识库进行推理并附带时间戳免责声明”，保障对话链路永不崩溃中断。

---

### 3. LoopGuard 熔断器触发：“🚨 检测到连续 3 次重复调用相同工具，主动熔断！”
- **根因**：
  - 当大模型在解决复杂难题遇到挫折时（例如搜索结果为空或代码运行报错），可能会陷入“反复调用同一个工具查询相同关键词”的无休止死循环。
- **防死机设计**：
  - 在 8.2 / 8.13 中，我们手搓了 `LoopGuard` 守护线程。一旦检测到连续多次重复调用相同工具且入参一致，会立即主动掐断循环并返回错误引导，防止无限消耗用户的 API 额度。

| **网页排版挤压变形/重叠** | 浏览器缩放过大 (125%+) / 窗口太小 | 按 **`Cmd -`** 缩小至 80%~90% / 最大化窗口 | 3 秒 |
| **界面黑底黑字/文字看不清** | Dark Reader 等第三方暗黑扩展色彩反转 | 将 `127.0.0.1:7860` 加入暗黑插件白名单 | 5 秒 |
| **ModuleNotFoundError** | 未使用 `uv` 虚拟环境，跑到了全局 Python | `uv run python app.py` 或激活 `.venv` | 10 秒 |
| **401 Invalid API Key** | `.env` 不存在 / 复制了多余引号空格 | `cp .env.example .env`，填入纯净 Key 文本 | 20 秒 |
| **Windows 下 Bash 命令报错** | 系统为 Windows，缺少 Linux 命令解释器 | 使用 Git Bash / WSL2，或改用跨平台命令 | 1 分钟 |
| **代码视窗未找到源码文件** | 未在 `code/` 根目录下启动 `app.py` | 必须先 `cd 08_手搓Agent/code` 再启动 | 5 秒 |
| **Token 未压缩** | 历史总 Token 未达到压缩触发阈值 | 在 8.8 工作台中点击预设超长测试用例 | 5 秒 |
| **记忆持久化文件解析报错** | `gradio_agent_memory.json` 损坏 | 删除该 JSON 文件让系统自动重建 | 3 秒 |
