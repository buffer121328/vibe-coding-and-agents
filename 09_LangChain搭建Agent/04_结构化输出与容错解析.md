# 📋 9.4 结构化输出与容错解析

> **“在企业级应用中，大模型必须从‘天马行空的文科生’，驯化为‘严谨填表的理科生’。”**  
> 无论是将非结构化新闻提炼为财报数据库记录，还是向下游业务系统分发 JSON 消息，结构化输出都是 AI 工程落地的核心命门。

---

## 💡 为什么需要结构化输出？（生活比喻篇）

### 1. 自然语言与业务代码的鸿沟
大模型天然习惯用自然语言说话。如果你让它“输出一个 JSON”，它经常会出现以下问题：
- 在 JSON 外面包裹 \`\`\`json 开头和多余的寒暄客套话；
- 字段名写错（如把 `user_id` 拼成 `userId` 或 `id`）；
- 缺少逗号或双引号未闭合，导致 Python `json.loads()` 直接崩溃报错（Crash）。

### 2. 生活比喻：海关标准报关单与智能质检机器人
- **自由发散输出**：就像旅客口头向海关申报行李：“我带了两双鞋、大概三斤牛肉干，还有送朋友的几瓶酒” —— 计算机系统根本无法自动录入；
- **结构化约束（Pydantic）**：就像海关递给旅客的**标准化中英文报关单**，上面每一个空格都有严格的类型限制（如商品名称为字符串、单价为浮点数、数量必须大于 0）；
- **`with_structured_output()`**：就像在旅客填表时安排了一位**智能海关质检机器人**，不仅强制按表格格式填写，还会通过底层 Function Calling 协议确保 100% 符合数据规范！

## 🏛️ LangChain 1.x 的结构化输出机制对比

在 LangChain 1.x 中，主要推荐使用现代原生 `.with_structured_output()`，兼顾经典 `JsonOutputParser`：

| 方案模式 | 底层技术原理 | 优点 | 缺点 / 适用场景 |
| :--- | :--- | :--- | :--- |
| **`llm.with_structured_output(Model)`** 🌟 (强烈推荐) | 模型原生 Tool/Function Calling 或 JSON Schema 强制约束 | 格式准确率最高（接近 100%），支持 Pydantic 字段类型与数值范围校验，免除正则清洗。 | 需要大模型本身支持 Function Calling 能力（如 GPT 系列、DeepSeek-V3 系列、Claude 系列）。 |
| **`JsonOutputParser`** | 在 Prompt 中注入 JSON 格式规范与字段说明，外置解析器容错提取 | 兼容不支持 Function Calling 的轻量或开源端侧小模型。 | 若模型产生幻觉或语法错误，偶尔需要结合 OutputFixingParser 自动重试修复。 |

> 🆕 **1.x 进阶：`create_agent` 也支持结构化输出**。9.9 的 `create_agent` 可通过 `response_format=` 参数指定 Pydantic 模型，让**整个 Agent 的最终答复**（而非单次 LLM 调用）都强制符合 Schema，适合“对话结束后自动生成报表/单据”的业务场景。

## 💻 核心实操：Pydantic 实体建模与信息抽取

### 1. 定义强类型金融研报 Pydantic Schema

```python
# code/s04_structured_output.py
from typing import List
from pydantic import BaseModel, Field

class KeyMetric(BaseModel):
    name: str = Field(description="指标名称，如营收、净利润、MAU")
    value: str = Field(description="指标数值，如 158.6 亿元、+28.5%")
    evaluation: str = Field(description="指标评价：超预期 / 符合预期 / 不及预期")

class FinancialReportAnalysis(BaseModel):
    company_name: str = Field(description="企业全称或股票标的")
    report_period: str = Field(description="财报所属季度或年份，如 2025Q3")
    core_summary: str = Field(description="100 字以内的核心经营亮点与痛点摘要")
    sentiment_score: int = Field(description="研报情绪评分，0 到 100 分", ge=0, le=100)
    key_metrics: List[KeyMetric] = Field(description="核心财务业务指标清单")
    risk_factors: List[str] = Field(description="面临的主要风险清单")
    rating: str = Field(description="综合投资评级：买入 / 增持 / 中性 / 卖出")
```

### 2. 使用 with_structured_output() 一键提取非结构化新闻

```python
from langchain_core.prompts import ChatPromptTemplate
from s01_model_io import get_chat_model

llm = get_chat_model()
# 绑定结构化模型
structured_llm = llm.with_structured_output(FinancialReportAnalysis)

news_text = """
【TechStar 2025年第三季度财报公布】
TechStar 智能科技今日公布最新三季度业绩：本季度实现总营业收入 158.6 亿元，同比增长 28.5%，大幅超出市场预期的 140 亿元；
其中云计算与 AI 业务营收占比达 42%，成为第一大支柱。净利润为 24.1 亿元，同比增长 12%，表现稳健符合预期。
然而，公司海外业务受到汇率波动和地缘供应链限制，海外增速放缓至 5%；同时研发投入由于大模型训练增加 45%，给短期毛利带来一定压力。
综合来看，管理层对 AI 全年商业化落地充满信心，券商多数给出'买入'评级。
"""

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名资深金融研报分析师，请从给定文本中提炼标准财报结构。"),
    ("human", "{text}")
])

chain = prompt | structured_llm

# 运行链：返回的直接就是强类型的 FinancialReportAnalysis 实例！
result: FinancialReportAnalysis = chain.invoke({"text": news_text})

print(f"企业名称: {result.company_name}")
print(f"情绪评分: {result.sentiment_score}/100")
print(f"评级: {result.rating}")
for m in result.key_metrics:
    print(f"  - {m.name}: {m.value} ({m.evaluation})")
```
