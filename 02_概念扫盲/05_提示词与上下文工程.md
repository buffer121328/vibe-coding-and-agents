# 2.5 提示词与上下文工程：从写好一句 Prompt 到喂饱整个 Context

> 提示词工程是教你“怎么跟 AI 提要求它才听得最懂”，而上下文工程则是“在 AI 动笔之前，把图纸、说明书和现成资料精准塞进它的工位”，让它绝不靠脑补瞎猜！

***

## 💬 什么是提示词（Prompt）？从最基础开始

**提示词（Prompt）** 就是你**发给大模型的那段文字指令**——可以是一个问题、一段需求描述，甚至一整份代码和文档。你问什么、怎么问，直接决定 AI 答什么、怎么答。

- **日常生活比喻**：就像给新来的员工交代工作。你说一句“把这事办了”和说清楚“什么时间、什么标准、注意什么、交付什么”，员工做出来的结果天差地别。
- **一个最直观的对比**：

| 差提示词 | 好提示词 |
| :--- | :--- |
| “帮我写个 Python 脚本” | “用 Python 写一个脚本：读取当前目录所有 CSV 文件，合并后按日期排序，输出到 result.csv；遇到空文件要跳过并打印警告。” |
| “解释一下这个报错” | “下面代码运行时报 `NameError: name 'x' is not defined`，请先解释原因，再给出修复后的完整代码。” |

### System Prompt 与 User Prompt 的区别

在真正的工程中，提示词分成两大来源：

| 类型 | 谁写的 | 作用 | 例子 |
| :--- | :--- | :--- | :--- |
| **System Prompt（系统提示词）** | 开发者 / 工具预先设定 | 定调子、定规矩，全程生效 | “你是一位资深 Python 工程师，回答要简洁，先给结论再解释” |
| **User Prompt（用户提示词）** | 用户每次提问 | 本次任务的具体诉求 | “帮我 review 一下这个函数有没有 bug” |

> 💡 你在 Cursor、Claude Code 里见到的 `.cursorrules` / `AGENTS.md`，本质就是**系统提示词**——它们决定了 AI 的“人设与规矩”，也是后面上下文工程的核心载体。

### 少样本示例（Few-shot）：给 AI 一两个“标准答案模板”

除了用文字描述要求，更高效的一招是在提示词里直接放 1~3 个**输入输出示例**，AI 就会照着示例的格式来回答：

```text
【Few-shot 示例：让 AI 做文本分类】
示例1：内容=“今天天气真好”       → 类别=【天气】
示例2：内容=“iPhone 又降价了”    → 类别=【科技】
请分类：内容=“这家餐厅的牛排太嫩了” → 类别=？
```

- **日常生活比喻**：给新员工看两份“做好的样板”，TA 立刻就知道交付格式长什么样了；
- **为什么有效**：模型是“照葫芦画瓢”高手，给示例往往比反复强调“请按 XX 格式输出”更管用；
- **适用场景**：抽取 JSON、格式转换、分类打标、风格模仿。

## ⚠️ 上下文陷阱：“迷失在中间（Lost in the Middle）”

很多新手把 10 万字的长文档一股脑全塞给大模型，结果发现 AI 经常看漏关键条款。

- **日常生活比喻**：
  - 想象你给老板提交了一份 200 页的年度总结报告。
  - 老板翻了翻第一页的摘要（开头印象深刻），又看了看最后一页的结论（结尾印象深刻），而夹在第 85 页的那个关键建议，老板**完全看漏了**！
- **工程避坑指南**：
  - **最核心的硬性指令、最关键的表结构定义，一定要放在上下文的最前面（System Prompt）或最后面（靠近提问处）**，避免放在海量资料的正中间！

## ⚡ 为什么现代 AI 对话越来越快？揭秘 KV Cache（预制菜大比喻）

在开发中你可能会发现：第一次向 AI 发送一个大项目时比较慢，但后续多轮对话时，AI 几乎瞬间就开始打字，而且费用大幅下降。

## ⚖️ 提示词工程 vs 上下文工程对比矩阵

| 维度           | 提示词工程 (Prompt Engineering)      | 上下文工程 (Context Engineering)               |
| :----------- | :------------------------------ | :---------------------------------------- |
| **日常生活类比**   | 思考“如何把需求说得动听清晰”                 | 思考“如何把施工现场的图纸和工具备齐”                       |
| **核心操作**     | 调整句式、角色扮演（Role）、提供少样本（Few-shot） | 编写 `.cursorrules`、注入 RAG 知识库、挂载 MCP 实时数据库 |
| **解决的痛点**    | 让 AI 听懂你的意图和输出格式                | 彻底根治 AI 编造不存在的假 API 与版本错乱问题               |
| **2026 年地位** | 基础基本功                           | **决定 Agent 生产力上限的核心竞争力**                  |
