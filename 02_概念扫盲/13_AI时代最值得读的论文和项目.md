# 2.13 AI 时代最值得读的论文、项目、Skills 市场与 MCP 教程

查阅资料像搭建自己的书架：先放常用教材，再按遇到的问题补充专门书籍。本节整理与前面概念直接相关的论文、教学项目和扩展资源，并说明阅读时应该关注什么。无需把所有项目都装一遍，也不必先读完全部论文才能开始实践。

### 1. [《Attention Is All You Need》](https://arxiv.org/abs/1706.03762) (Google, 2017)
- **arXiv 链接**: [https://arxiv.org/abs/1706.03762](https://arxiv.org/abs/1706.03762)
- **阅读价值**：**理解 Transformer 的起点**。
- **核心贡献**：提出以注意力为核心的 Transformer 架构，在机器翻译任务上验证了效果与并行训练优势，并非首次提出所有形式的注意力机制。

### 2. [《Language Models are Few-Shot Learners》 (GPT-3)](https://arxiv.org/abs/2005.14165) (OpenAI, 2020)
- **arXiv 链接**: [https://arxiv.org/abs/2005.14165](https://arxiv.org/abs/2005.14165)
- **阅读价值**：**开启 In-Context Learning（上下文学习）大模型时代**。
- **核心贡献**：证明了只要模型规模足够大，不需要重新训练修改权重，只要在提示词里给 AI 示范 1~2 个例子（Few-Shot），模型可以利用示例适应部分任务；不意味着任意新任务都能解决。

### 3. [《ReAct: Synergizing Reasoning and Acting in Language Models》](https://arxiv.org/abs/2210.03629) (普林斯顿 & Google, 2022)
- **arXiv 链接**: [https://arxiv.org/abs/2210.03629](https://arxiv.org/abs/2210.03629)
- **阅读价值**：**理解推理与行动结合的经典研究**。
- **核心贡献**：提出了“边思考、边行动、边观察（Thought ➔ Action ➔ Observation）”的闭环，研究推理记录与外部行动交替进行的效果。

### 4. [《Reflexion: Language Agents with Verbal Reinforcement Learning》](https://arxiv.org/abs/2303.11366) (MIT & 普林斯顿, 2023)
- **arXiv 链接**: [https://arxiv.org/abs/2303.11366](https://arxiv.org/abs/2303.11366)
- **阅读价值**：**通过语言反馈改进后续尝试**。
- **核心贡献**：教会了 Agent 在任务失败后不要瞎猜，而是写下一段自我反思：“我刚才为什么会写错？”，带着教训在下一次尝试中成功通关。

### 5. [《Generative Agents: Interactive Simulacra of Human Behavior》](https://arxiv.org/abs/2304.03442) (斯坦福大学, 2023)
- **arXiv 链接**: [https://arxiv.org/abs/2304.03442](https://arxiv.org/abs/2304.03442)
- **阅读价值**：**观察记忆、规划与群体行为的研究**。
- **核心贡献**：给 25 个 AI 居民赋予长期记忆、每日规划与社交沟通能力，AI 们在小镇上自主开派对、竞选市长、传八卦，奠定了 Multi-Agent 记忆与规划体系。

### 6. [《SWE-bench: Can Language Models Resolve Real-World GitHub Issues?》](https://arxiv.org/abs/2310.06770) (普林斯顿, 2023)
- **arXiv 链接**: [https://arxiv.org/abs/2310.06770](https://arxiv.org/abs/2310.06770)
- **阅读价值**：**理解真实仓库任务评估**。
- **核心贡献**：用 2294 个真实的 GitHub 历史 Bug 取代了玩具代码测试题，为仓库级问题修复提供了可复现的评估任务。

### 7. [《LoRA: Low-Rank Adaptation of Large Language Models》](https://arxiv.org/abs/2106.09685) (微软, 2021)
- **arXiv 链接**: [https://arxiv.org/abs/2106.09685](https://arxiv.org/abs/2106.09685)
- **阅读价值**：**大模型轻量化高效微调的开山之作**。
- **核心贡献**：发明了“外挂式旁路低秩矩阵”，减少需要训练的参数；实际资源节省与模型规模、训练设置和硬件有关。

### 8. [《DeepSeek-R1 Technical Report》](https://arxiv.org/abs/2501.12948) (DeepSeek, 2025)
- **arXiv 链接**: [https://arxiv.org/abs/2501.12948](https://arxiv.org/abs/2501.12948)
- **阅读价值**：**理解推理模型训练与评估**。
- **核心贡献**：分别讨论 R1-Zero 的强化学习探索与 R1 的多阶段训练流程，不能将二者都概括为完全不使用监督数据。

## 二、配合实践阅读的项目：从手搓原理到工业级 Harness

以下 4 个项目代表了现代 Agent 从“教学实战”到“生产级 Harness 架构”的演进脉络：

---

### 1. [Hello-Agents (Datawhale)](https://github.com/datawhalechina/hello-agents)
- **GitHub 地址**: [https://github.com/datawhalechina/hello-agents](https://github.com/datawhalechina/hello-agents)
- **核心定位**: 国内开源社区 Datawhale 打造的 Agent 全栈实战指南。
- **适合关注的内容**：
  - 从基础组件开始，带你使用纯原生 Python，从 0 到 1 手写出属于你自己的 **ReAct 闭环、Memory 记忆系统、MCP 协议与多智能体协作框架**；
  - 包含完整的阶段式教学与真实场景案例，非常适合打牢底层基本功。

---

### 2. [Learn-Claude-Code (shareAI-lab)](https://github.com/shareAI-lab/learn-claude-code)
- **GitHub 地址**: [https://github.com/shareAI-lab/learn-claude-code](https://github.com/shareAI-lab/learn-claude-code)
- **核心定位**: 专注于通过简化实现讲解类似编码智能体的运行过程，并非官方产品源码或完整复刻 的开源项目。
- **适合关注的内容**：
  - 深入剖析 `Agent Product = Model + Harness` 核心设计哲学；
  - 教你如何手写一个极简版（Nano-Harness）的终端代码智能体，搞懂工具调用、命令权限审批拦截与循环调度的底层实现。

---

### 3. [DeerFlow (ByteDance)](https://github.com/bytedance/deer-flow)
- **GitHub 地址**: [https://github.com/bytedance/deer-flow](https://github.com/bytedance/deer-flow)
- **核心定位**: 字节跳动开源的“SuperAgent”深度任务执行与编排 Harness 框架。
- **适合关注的内容**：
  - **长任务执行**：专为研究、深度写代码、复杂报告生成等长周期任务设计；
  - **Docker 沙箱隔离执行**：内置完整的文件系统、Bash 终端与沙箱隔离执行环境；
  - **动态子智能体分工**：基于 LangGraph 与 LangChain 架构，自动拆解并唤醒 Planner、Researcher、Coder、Reporter 等子 Agent 协同作业。

---

### 4. [DeepAgents (LangChain 官方)](https://github.com/langchain-ai/deepagents)
- **GitHub 地址**: [https://github.com/langchain-ai/deepagents](https://github.com/langchain-ai/deepagents)
- **核心定位**: LangChain 官方推出的新一代包含规划、文件处理等组件的智能体运行框架。
- **适合关注的内容**：
  - 摆脱了传统的简单一问一答，深度支持**显式任务规划（Explicit TODO Planning）**；
  - 支持**层级化子 Agent 委派（Hierarchical Delegation）**，每个子任务拥有独立的隔离上下文；
  - 原生提供持久化记忆（Persistent Memory）与人在回路（HITL）高级控制。

### 先区分规范、示例与资源目录

- [Agent Skills](https://agentskills.io)提供格式与集成规范，不是“所有技能都经过审计”的市场。
- [Anthropic 技能示例](https://github.com/anthropics/skills)可用于观察技能的目录与写法，使用前仍要检查所需依赖和适用范围。
- 社区资源目录用于发现项目，不代表目录维护者为每个脚本的行为或兼容性担保。

下载前先看 `SKILL.md`、配套脚本和要求的环境变量。一个排版技能如果要求访问无关目录，就需要进一步查明原因。安装后用一份测试材料运行，确认输出、写入位置和实际调用的工具。

### 1. 官方权威入门教程
- **[Model Context Protocol 官方入门文档](https://modelcontextprotocol.io/quickstart)**：手把手教你如何用 TypeScript 或 Python 编写你自己的第一个 MCP Server；
- **[Anthropic 官方 MCP SDK 与指南](https://docs.anthropic.com/en/docs/build-with-claude/mcp)**：深入学习客户端与服务端的通信架构与安全规范。

### 2.  MCP 插件与服务器宝库
- **[Awesome MCP Servers (GitHub 社区精选)](https://github.com/punkpeye/awesome-mcp-servers)**：
  - 汇总了全球数百款高质量开箱即用 MCP Server（涵盖 SQLite、Postgres、Slack、Puppeteer、Git、Docker 等）；
- **[Anthropic 官方 MCP Servers 仓库](https://github.com/modelcontextprotocol/servers)**：
  - 官方维护的工业级标准插件集合。

### 3. 安装之前，先检查维护状态

[MCP 官方参考服务器](https://github.com/modelcontextprotocol/servers)主要用于展示能力与实现方式，并不是所有服务都适合直接承担正式业务。早期 GitHub、PostgreSQL 等参考实现已归档，安装时应查看现行维护者与说明。

第三章的 [Hooks、MCP 与技能配置](../03_脚手架搭建/06_Hooks机制_MCP与Skills配置.md)会使用限定目录的文件服务作为练习。先完成一个不依赖外部账户的例子，再接入数据库或其他业务系统，更容易区分连接、认证与权限问题。

## 怎样安排阅读顺序

先围绕一个具体问题阅读。例如不理解工具调用，就先读 ReAct 的流程与一个简化实现；不理解检索为什么失败，就先看检索流程、切块与评估；需要本地运行模型时，再深入量化。

论文的阅读也可以分层：第一遍看摘要、问题设定和流程图；第二遍看实验输入、比较方法与评价指标；遇到确实需要理解的公式，再回到相应背景知识。不要只记住作者给出的最好成绩。

## 用四个问题整理一篇论文

1. 它解决什么问题，之前的方法为什么不够？
2. 它改变了系统中的哪个环节？
3. 效果在哪些任务与设置下得到验证？
4. 哪些限制会影响自己的项目？

例如 LoRA 的重点是减少训练参数，并不代表所有模型都能在任意家用电脑上微调。SWE-bench 的重点是仓库级任务评估，也不能把某一榜单成绩直接当成你的项目成功率。

## 读项目源码，从一次完整执行开始

先找到入口，再追踪一个输入如何经过模型、工具、状态和输出。记录每一步的数据结构与可能失败的位置，不必一开始就读完全部目录。

可以选择一个最小问题：“用户要求读取文件时，工具名称在哪里注册？参数在哪里验证？读取失败后，模型会得到什么？”围绕这条路径阅读，通常比逐个文件顺序浏览更容易理解设计。

教学项目还要与完整产品区分。为了突出原理，例子可能省略权限、并发、恢复和日志脱敏。学习时可以主动标注这些缺口，再思考如何补上，而不是直接把演示代码当作正式服务。

## 保留能复查的学习记录

每次阅读保存来源链接、所读版本、解决的问题和一条自己的验证。例如修改一次最大循环次数，观察智能体怎样停止；更换一份没有答案的资料，观察问答系统会不会编造。

如果记录的是框架用法，还应注明包版本或提交号。网络文章与仓库都会变化，没有版本的信息很容易在下次运行时失效。最终积累下来的应是理解与验证方法，而不只是一长串收藏链接。
