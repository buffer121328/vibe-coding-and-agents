# 15.1 Python 基础

> 本节整理 20 道 Agent 开发岗位常问的 Python 基础题。答案刻意写成面试现场可以直接表达的连续段落：先解释机制，再说明工程影响，最后给出适合 Agent 或服务端的例子。不要把答案当成固定台词，最好结合自己的项目经历补充证据。

## 一、语言核心：数据模型与对象机制

### 1. 可变对象与不可变对象有什么区别？

**真实问法**：哪些 Python 对象可变？可变默认参数为什么会出问题？

**参考答案**：`list`、`dict`、`set` 和大多数自定义类实例是可变对象，`int`、`float`、`str`、`bytes`、`tuple` 和 `frozenset` 通常是不可变对象。不可变表示对象创建后不能原地改变；看起来像修改的操作实际上会创建新对象。`tuple` 只是外层不可变，如果里面放了一个列表，列表仍然可以修改。

默认参数在函数定义时求值，而不是每次调用时求值。因此 `def add(x, items=[]):` 会让所有省略 `items` 的调用共享同一个列表。正确写法是使用 `None` 作为哨兵，在函数体内新建列表。多租户 Agent 中如果把会话状态放进可变默认参数，就可能出现用户之间串数据。

### 2. `==` 和 `is` 有什么区别？

**真实问法**：为什么两个整数有时 `is` 也为真？

**参考答案**：`==` 比较值，可以被 `__eq__` 重载；`is` 比较对象身份，表示两个变量是否指向同一个对象。整数驻留、字符串驻留和编译器常量折叠会让某些相同字面量复用对象，但这些是实现细节，不能用来判断值相等。

工程上判断 `None`、`True`、`False` 这类单例时使用 `is`，其他值比较使用 `==`。不要写 `x is 1` 或依赖某个整数范围内的缓存行为，因为换解释器、换编译方式或换代码位置后结果可能不同。

### 3. 浅拷贝和深拷贝怎么区分？

**真实问法**：为什么复制一个嵌套字典后，改内层数据会影响原对象？

**参考答案**：浅拷贝只创建最外层容器，内部元素仍然引用原对象；深拷贝会递归复制嵌套对象。`dict.copy()`、`dict(a)` 和 `{**a}` 都是浅拷贝。对包含列表、字典或自定义对象的状态直接浅拷贝，修改内层就可能污染原状态。

`copy.deepcopy()` 能得到更独立的副本，但会增加时间和内存，也要处理循环引用、锁、文件句柄等不能简单复制的对象。工程中通常更推荐写时复制，只复制即将修改的那一层，例如 `{**state, "config": {**state["config"], "retries": 5}}`。这对 Agent 的多分支工作流状态尤其重要。

### 4. 装饰器是怎么工作的？

**真实问法**：带参数的装饰器怎么写？为什么要使用 `functools.wraps`？

**参考答案**：`@deco` 是 `fn = deco(fn)` 的语法糖。带参数的装饰器需要三层函数：外层接装饰器参数，中层接被装饰函数，内层接真实调用参数。内层函数通过闭包记住外层的配置和原函数。

`functools.wraps` 会复制原函数的名称、文档、模块和 `__wrapped__` 等元信息，否则日志、调试器、测试和依赖注入框架看到的可能只是 `wrapper`。装饰器在函数定义或模块导入时执行，包装函数体则在调用时执行，所以不应在装饰器构造阶段做昂贵的网络连接。重试、计时、权限检查和 tracing 都可以用装饰器表达，但装饰器内部仍要保留取消、异常和幂等语义。

### 5. 迭代器和生成器有什么区别？

**真实问法**：`yield` 为什么可以省内存？

**参考答案**：迭代器实现了 `__iter__` 和 `__next__` 协议，可以逐个产生元素；生成器是使用 `yield` 编写的迭代器。调用生成器函数时不会立即执行函数体，而是返回一个保存执行现场的生成器对象。

`yield` 会暂停函数并保留局部变量和下一条执行位置，下一次 `next()` 再继续；`return` 会结束迭代并触发 `StopIteration`。生成器通过惰性求值一次只产生一个元素，适合逐行读取大文件、流式处理和 Agent 的增量输出，但它通常只能消费一次，不能像列表一样随意下标访问。

### 6. 闭包和延迟绑定是什么？

**真实问法**：`[lambda: i for i in range(3)]` 为什么调用后都得到 2？

**参考答案**：闭包可以访问定义它的外层作用域变量。Python 闭包默认捕获变量本身，而不是循环当时的值，所以三个 lambda 都引用同一个 `i`；循环结束后 `i` 是 2，调用时就都使用 2。这叫延迟绑定。

可以用默认参数、闭包工厂或 `functools.partial` 固定当前值，例如 `[lambda i=i: i for i in range(3)]`。写工具注册表和中间件配置时也要注意这个问题，注册动作如果只保存了可变配置对象的引用，之后修改配置可能让已注册函数的行为悄悄改变。

### 7. 上下文管理器的原理是什么？

**真实问法**：`with` 语句如何保证资源释放？`__exit__` 返回值有什么意义？

**参考答案**：`with resource as value` 会调用 `resource.__enter__()`，把返回值绑定给 `value`，退出代码块时无论是否发生异常都会调用 `__exit__(exc_type, exc_value, traceback)`。因此文件、锁、数据库连接和 HTTP 会话都适合用上下文管理器管理。

`__exit__` 返回真值时会吞掉异常，返回假值或 `None` 时异常继续传播。除非异常确实已经被完整处理，否则不应随意返回 `True`。`contextlib.contextmanager` 可以把生成器包装成上下文管理器，`yield` 前写进入逻辑，`yield` 后写清理逻辑，异常处理要用 `try/finally` 保证资源一定释放。

## 二、异常、并发与 GIL

### 8. GIL 是什么？多线程、进程和异步如何选？

**真实问法**：CPU 密集和 I/O 密集任务分别怎么并发？

**参考答案**：传统 CPython 的 GIL 会限制同一时刻只有一个线程执行 Python 字节码。线程在等待网络、磁盘或某些会释放 GIL 的 C 扩展时可以让出执行权，因此多线程适合 I/O 密集任务；纯 Python CPU 计算用多个线程通常不能获得真正的多核并行，应考虑多进程或下沉到释放 GIL 的原生库。

`asyncio` 是单线程协作式调度，任务在 `await` 处主动让出控制权，适合大量并发 I/O，但任何阻塞调用都会卡住整个事件循环。Agent 服务常采用 asyncio 处理模型 API 和工具网络请求，使用线程池承接同步 SDK，使用进程池或原生扩展处理 CPU 重活。新版本 CPython 提供了可选的 free-threaded 构建，但生态兼容和部署选择仍要单独验证，不能据此假设所有生产环境都没有 GIL。

### 9. `try`、`except`、`else`、`finally` 怎么配合？

**真实问法**：为什么不建议裸 `except`？

**参考答案**：`try` 放可能抛异常的代码，匹配到异常时执行 `except`；没有异常时执行 `else`；`finally` 无论是否成功、是否提前 `return` 都会执行。把成功路径放在 `else` 中可以避免把它产生的异常误认为是被保护代码的异常。

`Exception` 不包含直接继承自 `BaseException` 的 `KeyboardInterrupt`、`SystemExit` 和 `GeneratorExit`，所以业务代码通常捕获具体异常或 `Exception`，不要用裸 `except` 把退出信号吞掉。处理不了的异常应继续抛出，并用 `raise NewError(...) from exc` 保留根因。工具调用可以在边界层记录、重试或降级，但不能静默返回一个看似成功的假结果。

### 10. 协程、`await` 和事件循环是什么关系？

**真实问法**：`async def` 调用后是不是立刻执行？能否在 async 函数里直接调用 `requests.get`？

**参考答案**：调用 `async def` 返回协程对象，函数体要等协程被 `await`、创建任务并由事件循环调度后才执行。`await` 会在等待对象未就绪时暂停当前协程，把控制权交给事件循环；事件循环负责在 I/O 就绪或定时器到期后恢复任务。

在 async 函数中直接调用阻塞的 `requests.get` 会卡住整个事件循环，其他协程也无法运行。应使用异步 HTTP 客户端，或用 `asyncio.to_thread` 把同步函数放进线程池。Jupyter 等环境已经运行事件循环时通常直接 `await main()`，不要再次调用 `asyncio.run()`。

### 11. 同步 SDK 如何安全接入异步代码？

**真实问法**：只有同步客户端时，怎么避免阻塞事件循环？

**参考答案**：最简单的方式是 `await asyncio.to_thread(sync_fn, *args, **kwargs)`，让同步函数在线程池执行；需要控制并发或复用线程时，可以创建自定义 `ThreadPoolExecutor` 并使用 `run_in_executor`。如果 SDK 提供官方异步客户端，长期方案通常是直接使用异步版本，减少线程切换和资源管理复杂度。

线程池并不能把 CPU 密集任务变成并行计算，默认线程数也会限制吞吐。封装工具时要把取消、超时和异常传递设计清楚：取消等待不一定能强制中断已经进入同步库的线程，必要时要在库层设置自己的请求超时。

### 12. 多线程、多进程、asyncio 如何做选型？

**真实问法**：为什么 Agent 服务常见 asyncio 加线程池？

**参考答案**：多线程适合并发量中等、需要调用同步 I/O 库的场景；多进程可以绕过传统 CPython GIL 并提供更强隔离，但进程创建、序列化和进程间通信成本较高；asyncio 适合大量 I/O 等待，任务和连接的管理开销较小。

选择应结合任务类型、并发量、下游限制、内存预算和故障边界。Agent 请求往往大部分时间在等待模型、数据库或 HTTP 工具，因此用 asyncio 管理连接，再把无法异步化的 SDK 放入受限线程池，通常能兼顾吞吐和接入成本；需要图像处理、压缩或复杂计算时再使用进程池或原生扩展。

### 13. GIL 是否能保证线程安全？

**真实问法**：多个线程同时修改 `dict` 会不会出问题？

**参考答案**：GIL 不是业务级锁，也不保证复合操作的原子性。某些单步容器操作在特定 CPython 版本中表现为原子，但“先检查再修改”“读取、计算、写回”这类多步逻辑仍可能交错。不同解释器和未来实现也不应依赖这些细节。

需要保护业务不变量时应使用 `threading.Lock`、线程安全队列、原子外部存储或不可变写时复制。异步单线程同样可能在两个 `await` 之间发生逻辑竞态，因此要围绕完整状态转换设计锁和消息协议，而不是只看物理线程数。

## 三、工程习惯：类型、环境与测试

### 14. 类型标注、`TypedDict`、`Protocol` 和 Pydantic 有什么区别？

**真实问法**：类型标注能否在运行时阻止错误？

**参考答案**：`typing` 中的类型标注主要服务于阅读和静态检查工具，如 pyright 或 mypy，Python 默认不会因为标注不匹配而在运行时自动拒绝。`TypedDict` 描述普通字典的键和值形状，`Protocol` 描述对象只要具备哪些方法和属性就可以被接受，体现结构化子类型。

Pydantic 在运行时校验和转换数据，并提供序列化与反序列化能力，适合配置、API 入参和模型结构化输出。可以用 Protocol 定义工具接口，用 TypedDict 描述内部事件，用 Pydantic 校验来自网络或 LLM 的不可信输入，三者解决的是不同层次的问题。

### 15. 虚拟环境、依赖声明和锁文件分别做什么？

**真实问法**：`requirements.txt` 和 `uv.lock` 的区别是什么？

**参考答案**：虚拟环境隔离项目安装的包，避免项目之间互相污染；`pyproject.toml` 或 `requirements.txt` 描述项目需要哪些直接依赖，通常允许版本范围；锁文件记录完整的传递依赖、精确版本和校验信息，用于复现同一套环境。

`uv`、Poetry 等工具把环境创建、依赖解析和锁定整合起来，但核心原则不变：直接依赖写清楚，锁文件提交仓库，CI 使用冻结模式安装。Agent 项目经常同时依赖多个 SDK 和 Pydantic 版本，锁文件和依赖树能帮助定位“本地能跑、部署失败”的差异。

### 16. pytest 的 fixture 和 monkeypatch 有什么用？

**真实问法**：如何测试一个会调用外部 API 的函数？

**参考答案**：fixture 用于组织测试前置、测试数据和清理逻辑，可以管理临时目录、数据库、配置或假客户端；`yield` 前准备资源，`yield` 后释放资源。monkeypatch 可以临时替换模块属性、环境变量或函数，测试结束后自动恢复。

测试外部 API 时不应让单元测试真的发请求或消耗额度，而要注入假的客户端，断言传入参数、错误处理和结果转换是否正确。网络和模型可以在少量集成测试中验证，主测试套件应保持离线、快速、可重复，并覆盖超时、限流、空响应和结构化输出失败。

### 17. Review AI 生成的 Python 代码时重点看什么？

**真实问法**：AI 写代码很快，你如何判断它能不能进生产？

**参考答案**：我会先确认函数边界、类型和副作用，检查是否把客户端、配置和全局状态硬编码在函数内部；再检查异常是否被吞掉、超时和取消是否传递、重试是否幂等、资源是否在异常路径释放。可变默认参数、深浅拷贝、闭包延迟绑定、async 中调用阻塞函数和无界缓存是 AI 代码中很常见的隐患。

然后用边界条件验证实现：空输入、`None`、重复请求、并发访问、部分失败、超大响应和进程重启。最后关注可观测性和安全性，确保日志不泄露 Token 或用户数据，关键决策有追踪信息，失败时不会返回“看起来正确”的伪结果。AI 生成代码最终仍需要人对行为负责。

### 18. `dict` 和 `set` 的底层有什么共同点？

**真实问法**：为什么列表不能作为字典 key？

**参考答案**：`dict` 和 `set` 都基于哈希表，平均查找和插入接近 O(1)。字典 key 或集合元素必须可哈希，并且对象相等时哈希值必须相同。列表可变，内容改变后哈希值可能改变，因此 Python 不允许列表作为 key；元组只有在内部元素都可哈希时才可作为 key。

自定义类如果重写 `__eq__`，要同时正确处理 `__hash__`，并保证参与哈希的字段在对象进入集合后不再变化。字符串哈希还可能使用进程级随机种子，因此不要把 `hash("x")` 当作跨进程稳定 ID。缓存 key、去重集合和上下文索引都要遵守这些规则。

## 四、开放题

### 19. 讲一个你印象最深的 Python 踩坑。

**考察点**：确认候选人是否真正写过、调过和修过代码。

**参考答案**：建议按“现象、定位、根因、修复、防再犯”的顺序讲一个真实案例。例如我曾经给工具函数加了一个列表默认参数，单测只调用一次没有暴露问题，线上多次调用后发现不同请求的状态混在一起。定位签名后确认列表是在函数定义时创建的，所有调用共享同一个对象；我改成 `None` 哨兵并在函数内创建新列表，同时在 Review 规则和回归测试中加入这类检查。

如果案例发生在 Agent 项目中，可以继续说明它如何影响会话隔离、工具重试或上下文状态，以及你用什么日志、测试或类型约束防止复发。面试官更关心你是否能把一个问题闭环，而不是故事听起来多严重。

### 20. AI 都能写代码了，Python 基础还有必要学吗？

**考察点**：判断候选人是否理解 AI 时代工程师的责任边界。

**参考答案**：有必要，而且基础能力的价值从“手写每一行代码”转向“判断、集成和兜底”。AI 可以生成一个看似完整的函数，却不一定知道可变状态是否会串租户、异常是否会被吞掉、同步调用是否会卡住事件循环，也不一定理解业务的权限和成本边界。

因此 Python 基础直接决定我能否审查生成代码、把工具接入并发 Agent、设计可测试的接口，并在生产故障时读懂堆栈和状态。面试时我会用一个具体例子说明：AI 生成了带重试的网络调用，我发现它对非幂等请求重复提交、没有总截止时间，于是补上幂等键、退避和测试。基础不是和 AI 竞争写字速度，而是保证最终行为由人负责。
