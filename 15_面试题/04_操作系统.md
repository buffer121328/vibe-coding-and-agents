# 15.4 操作系统

> 本节整理 50 道面向后端、平台和 Agent 开发岗位的高频操作系统面试题。回答时要把概念落到进程、线程、内存、文件、I/O 和容器的实际行为上。遇到故障题，优先说明可观测证据和排查顺序。

## 一、内核、进程与线程

### 1. 用户态和内核态有什么区别？

**面试问法**：为什么程序不能直接访问所有硬件资源？

**参考答案**：用户态运行普通应用代码，权限受限；内核态运行操作系统内核和驱动，可以管理 CPU、内存、设备和进程。应用通过系统调用进入内核，请求文件读写、网络通信、创建进程等受保护操作，完成后再返回用户态。

权限边界可以隔离故障和恶意访问，但系统调用、上下文切换和数据拷贝也有成本。优化程序时不能把“少一次系统调用”当作永远正确，要结合批量 I/O、缓存和可观测性评估。

### 2. 进程和线程有什么区别？

**面试问法**：进程、线程分别拥有什么资源？

**参考答案**：进程是资源隔离和保护的基本单位，拥有独立的虚拟地址空间、文件描述符表和进程状态；线程是调度执行的基本单位，同一进程中的线程共享地址空间、堆和打开的文件，但拥有各自的栈、寄存器上下文和线程局部数据。

多进程隔离更强，一个进程崩溃通常不会直接破坏另一个进程，但创建和进程间通信成本更高。多线程共享数据方便、切换开销较小，却需要处理竞争、死锁和内存可见性。

### 3. PCB 和 TCB 记录什么？

**面试问法**：操作系统切换进程时需要保存哪些信息？

**参考答案**：PCB 通常记录进程标识、状态、调度信息、地址空间、打开文件和资源限制等；TCB 记录线程寄存器、栈指针、调度状态和线程局部信息。具体字段由操作系统实现，但核心是保存“下次如何从原位置继续执行”。

这些控制块还用于资源回收、信号处理、权限检查和调度统计。理解 PCB/TCB 有助于解释上下文切换为什么需要保存寄存器、切换地址空间和更新调度队列。

### 4. 进程有哪些常见状态？

**面试问法**：运行、就绪、阻塞之间如何转换？

**参考答案**：就绪表示具备运行条件但等待 CPU；运行表示正在 CPU 上执行；阻塞或等待表示在等 I/O、锁、信号等事件。运行中的进程耗尽时间片、被高优先级任务抢占或主动让出后回到就绪；等待事件完成后从阻塞进入就绪。

不同系统还会区分挂起、停止、僵尸等状态。排查服务卡顿时，要区分线程是在运行、排队等待 CPU，还是阻塞在 I/O 或锁上，单看进程数量无法判断原因。

### 5. 什么是上下文切换？

**面试问法**：线程切换为什么会有成本？

**参考答案**：上下文切换需要保存当前线程的寄存器和程序计数器，加载下一个线程的上下文，并可能切换地址空间、刷新或更新 TLB、污染 CPU 缓存。线程属于同一进程时，地址空间切换成本通常低于跨进程切换，但仍然需要调度和缓存恢复。

高并发并不等于创建无限线程。线程过多会增加调度、栈内存和上下文切换成本，最终吞吐下降。应使用线程池、异步 I/O 或多进程并结合 CPU、I/O 等待比例进行容量测试。

### 6. `fork` 和 `exec` 分别做什么？

**面试问法**：Unix 中启动一个新程序通常经历哪些步骤？

**参考答案**：`fork` 创建当前进程的副本，子进程继承地址空间、文件描述符等资源；现代系统通常使用写时复制，只有某一方修改页面时才真正复制。`exec` 用新程序的代码、数据和栈替换当前进程映像，但进程 ID 通常保持不变。

Shell 启动命令时常见流程是 fork 子进程，再由子进程 exec 目标程序，父进程根据需要等待。若 fork 后没有正确关闭不需要的文件描述符，可能导致管道无法结束或连接被意外保持。

### 7. 什么是僵尸进程和孤儿进程？

**面试问法**：子进程退出后为什么还会出现在进程表里？

**参考答案**：子进程结束后，内核仍保留退出状态和少量信息，等待父进程调用 `wait` 或 `waitpid` 回收，这段时间的子进程叫僵尸进程。孤儿进程是父进程先退出、子进程仍在运行的进程，通常会被系统中的特定收养进程接管。

僵尸多说明父进程没有正确回收子进程，不一定占用大量内存，但会耗尽进程表项。服务启动子进程时应处理 SIGCHLD、显式 wait，并在优雅关闭阶段等待或终止子进程。

### 8. 进程间通信有哪些方式？

**面试问法**：管道、消息队列、共享内存和 Socket 如何选？

**参考答案**：管道适合有亲缘关系进程的顺序字节流；消息队列按消息边界传递并可按类型或优先级获取；共享内存速度快但需要额外的锁或原子操作；Unix Socket 和网络 Socket 适合更通用的本机或跨主机通信。

选择取决于数据量、延迟、是否需要持久化、进程关系和故障隔离。共享内存并不是“零成本”，同步、生命周期和一致性都由应用负责，设计不当反而更难排查。

### 9. 共享内存为什么快？它有什么风险？

**面试问法**：为什么共享内存不需要每次拷贝？

**参考答案**：多个进程可以把同一物理内存页映射到各自的虚拟地址空间，读写时不必像管道那样在内核缓冲区和用户缓冲区之间反复复制，因此吞吐高、延迟低。

风险在于多个执行流同时修改共享数据会产生竞态，进程崩溃还可能留下不完整状态。需要使用进程间互斥锁、信号量、原子操作或版本协议，并明确谁负责初始化、扩容、清理和恢复。

### 10. 信号是什么？为什么不能把所有逻辑放进信号处理器？

**面试问法**：SIGTERM、SIGKILL、SIGINT 有什么区别？

**参考答案**：信号是操作系统向进程通知事件的异步机制。SIGTERM 通常表示请求程序优雅退出，程序可以捕获并清理；SIGINT 常由终端的 Ctrl+C 产生；SIGKILL 不能被捕获或忽略，内核会直接终止进程。

信号处理器可执行的操作受限，复杂逻辑、内存分配和非异步安全函数可能造成死锁或状态损坏。常见做法是在处理器中设置一个原子标志或写入自管道，再由主循环安全地执行关闭、刷新和资源释放。

### 11. 多线程和多进程如何选择？

**面试问法**：CPU 密集和 I/O 密集任务分别使用什么并发模型？

**参考答案**：CPU 密集任务需要多个核心并行，通常使用多进程、原生扩展或能释放解释器锁的运行时；I/O 密集任务在等待网络和磁盘时，线程或异步 I/O 可以提高并发。多进程隔离好但通信成本大，多线程共享内存方便但同步复杂。

选择应以测量为依据：看 CPU 利用率、I/O 等待、上下文切换、队列长度和尾延迟。对于 Agent 服务，常见组合是事件循环处理网络，线程池承接同步 SDK，进程池处理重 CPU 任务。

### 12. 用户态线程和内核线程有什么差别？

**面试问法**：为什么用户态协程可以创建很多个？

**参考答案**：用户态线程或协程由运行库调度，切换不必每次进入内核，栈和控制块较小，因此可以创建很多个；但如果其中一个执行阻塞系统调用，可能阻塞承载它的内核线程。内核线程由操作系统调度，可以被不同 CPU 并行执行，也能独立阻塞。

现代运行库常把大量用户态任务复用到少量内核线程上，并把阻塞操作移到专用线程池。关键不是名称，而是确认谁负责调度、阻塞会影响多大范围以及是否真正利用多核。

## 二、并发、同步与调度

### 13. 什么是竞态条件？

**面试问法**：为什么 `count += 1` 可能丢更新？

**参考答案**：当多个执行流访问共享状态，最终结果依赖它们交错顺序，而代码又没有保证正确同步，就产生竞态。`count += 1` 通常包含读取、计算和写回多个步骤，两个线程可能读到同一个旧值，导致一次更新被覆盖。

解决方式包括互斥锁、原子操作、消息传递、不可变数据和数据库原子更新。要保护的是完整的业务不变量，而不是只给某一行代码加锁；锁外的检查和锁内的修改必须处于同一临界区。

### 14. 互斥锁、信号量和自旋锁有什么区别？

**面试问法**：为什么锁不一定都是同一种？

**参考答案**：互斥锁用于保护临界区，通常同一时刻只有一个持有者；信号量维护一个计数，适合限制并发资源数量或实现生产消费；自旋锁在等待时忙循环，不立即睡眠，适合持锁时间极短且不能睡眠的内核场景。

用户态服务中长时间持有自旋锁会浪费 CPU，互斥锁也不能保护跨进程状态，除非使用进程共享的实现。选择同步原语要看等待时间、是否允许阻塞、资源数量和执行上下文。

### 15. 条件变量解决什么问题？

**面试问法**：生产者消费者为什么需要条件变量？

**参考答案**：条件变量让线程在某个条件不满足时释放关联的互斥锁并睡眠，条件可能满足后再被唤醒。生产者加入数据后通知消费者，消费者醒来后重新检查队列是否非空。

等待必须放在循环中，因为可能出现虚假唤醒，也可能多个线程竞争后条件再次不满足。条件变量本身不保存业务状态，真正的条件应由共享变量和互斥锁共同保护。

### 16. 死锁的四个必要条件是什么？

**面试问法**：死锁发生需要哪些条件？

**参考答案**：互斥、占有且等待、不可剥夺和循环等待同时成立时，系统可能死锁。线程 A 持有锁 1 等锁 2，线程 B 持有锁 2 等锁 1，就是典型循环等待。

破坏任意一个条件都能避免死锁，例如统一加锁顺序、一次性申请全部资源、允许抢占或使用超时和回滚。工程中还要设置锁等待监控和转储，避免只依赖理论上的代码审查。

### 17. 如何预防、避免和检测死锁？

**面试问法**：锁顺序和超时分别属于哪种策略？

**参考答案**：预防是通过设计破坏死锁必要条件，例如全局锁顺序；避免是根据当前资源状态判断是否进入安全状态，经典算法是银行家算法；检测是允许死锁发生，再通过等待图或超时发现并恢复。

应用服务更常采用明确的锁顺序、缩短临界区、`try_lock` 超时、失败回滚和周期性诊断。超时不能把死锁变成正确性问题，超时后必须保证已获取资源被释放，事务或状态能够回到一致状态。

### 18. 什么是优先级反转？如何缓解？

**面试问法**：低优先级线程持锁，为什么会阻塞高优先级线程？

**参考答案**：低优先级线程持有高优先级线程需要的锁，而中优先级线程不断运行，导致低优先级线程迟迟无法释放锁，高优先级线程反而被间接阻塞，这就是优先级反转。

常用缓解方式是优先级继承，让持锁线程临时提升优先级；或使用优先级上限、缩短临界区、避免高低优先级共享长锁。实时系统尤其关注这种问题，普通服务也应监控锁等待和尾延迟。

### 19. 常见 CPU 调度算法有哪些？

**面试问法**：先来先服务、时间片轮转和优先级调度怎么比较？

**参考答案**：先来先服务实现简单但可能让短任务被长任务拖住；时间片轮转让任务轮流运行，响应更公平；优先级调度优先执行重要任务，但低优先级任务可能饥饿。多级反馈队列会根据历史行为动态调整优先级。

调度目标包括吞吐、响应时间、周转时间、公平性和实时性，它们相互冲突。服务器线程池也会遇到类似权衡，应根据任务类型、截止时间和资源隔离设计队列和优先级。

### 20. 抢占式和非抢占式调度有什么区别？

**面试问法**：操作系统为什么要抢占线程？

**参考答案**：非抢占式调度要求线程主动让出 CPU 或阻塞后才切换，实现简单但一个长时间运行的任务会拖住其他任务。抢占式调度由时钟中断或更高优先级任务触发切换，响应更好，但需要保存更多状态并处理并发同步。

抢占不能保证应用逻辑自动安全，线程仍可能在共享数据更新到一半时被切换。用户态协程通常是协作式的，只有在 `await` 等显式让出点切换，因此阻塞调用会影响同一事件循环中的所有任务。

### 21. 什么是饥饿？如何使用老化机制？

**面试问法**：公平调度为什么还会让某些任务一直得不到 CPU？

**参考答案**：饥饿是某个任务长期得不到所需 CPU、锁或资源，虽然系统整体仍在运行。优先级队列、锁竞争和不公平的 I/O 调度都可能造成饥饿。

老化会随着等待时间增加任务优先级，让长期等待的任务最终得到服务。应用层还可以设置每个租户的配额、队列上限和最大等待时间，避免高优先级或高流量客户端永久占满共享资源。

## 三、虚拟内存与内存管理

### 22. 什么是虚拟内存？

**面试问法**：为什么每个进程都觉得自己拥有连续的大地址空间？

**参考答案**：虚拟内存把进程看到的虚拟地址映射到物理内存页或磁盘后备存储。每个进程拥有独立的地址空间，内核通过页表控制映射和权限，从而实现隔离、按需分配和共享库映射。

虚拟地址空间连续不代表物理内存连续。它带来保护和灵活性，但地址转换、页表和缺页处理都会产生成本，内存压力大时还可能触发换页和抖动。

### 23. 页表和 TLB 分别做什么？

**面试问法**：CPU 如何把虚拟地址转换成物理地址？

**参考答案**：页表记录虚拟页到物理页框的映射以及可读写、执行等权限。CPU 访问地址时先查 TLB，这是保存近期地址转换结果的高速缓存；TLB 命中就能快速完成转换，未命中则需要查询多级页表并把结果填回 TLB。

进程切换、页表规模和随机内存访问都会影响 TLB 命中率。大页可以减少页表项和 TLB 压力，但会增加内存浪费和分配复杂度，不应在没有测量时盲目启用。

### 24. 什么是缺页异常？

**面试问法**：访问内存为什么会进入内核？

**参考答案**：如果访问的虚拟页没有当前有效映射，CPU 会触发缺页异常进入内核。内核判断访问是否合法：若页面在磁盘或文件中，就把它装入物理内存并更新页表；若地址非法，则向进程发送段错误等异常。

缺页可能是首次访问按需分配，也可能需要真实磁盘 I/O。监控中要区分轻微缺页和重大缺页，后者频繁发生会显著增加延迟。

### 25. 什么是按需分页？

**面试问法**：程序启动时为什么不必把所有代码和数据都读进内存？

**参考答案**：按需分页只在页面第一次访问时加载或分配物理页，未访问的代码、数据和映射文件不占用实际内存。这减少启动时间和内存占用，也允许进程映射大于当前物理内存的地址空间。

代价是首次访问可能产生缺页延迟，访问模式随机时还会造成频繁换页。对延迟敏感服务可以通过预热、顺序访问、锁定关键页或合理的工作集控制降低抖动。

### 26. FIFO、LRU 和 Clock 页面置换有什么区别？

**面试问法**：为什么简单的 FIFO 可能不如 LRU？

**参考答案**：FIFO 淘汰最早进入内存的页，实现简单但不考虑访问频率，甚至可能出现 Belady 异常。LRU 淘汰最近最少使用的页，利用时间局部性，但精确记录每次访问成本较高。Clock 使用访问位近似 LRU，在开销和效果之间折中。

实际操作系统通常采用近似算法和多级队列，而不是维护完全精确的 LRU。选择置换策略要结合工作集、访问局部性和跟踪成本。

### 27. 什么是内存抖动？

**面试问法**：CPU 使用率下降但磁盘很忙，可能是什么原因？

**参考答案**：当进程工作集大于可用物理内存，页面不断被换出又很快换入，系统大部分时间花在处理缺页和磁盘 I/O 上，称为抖动。此时 CPU 可能没有真正执行有用计算，响应时间明显上升。

解决方向包括减少并发工作集、增加内存、改善访问局部性、限制缓存大小和调整进程内存分配。只提高 CPU 配额通常无效，应先看缺页率、交换区、RSS 和容器内存限制。

### 28. 什么是写时复制？

**面试问法**：`fork` 后为什么父子进程可以暂时共享内存？

**参考答案**：fork 后父子进程的页表可以指向同一物理页，并把页面标记为只读。任一方尝试写入时触发缺页异常，内核复制该页并让写入方获得自己的副本，这就是写时复制。

它能显著降低 fork 的初始成本，但如果父子进程都大量修改内存，复制成本会集中爆发。大进程 fork 后再执行新程序时要注意线程、文件描述符和内存峰值问题。

### 29. `mmap` 适合什么场景？

**面试问法**：内存映射文件和 `read` 有什么区别？

**参考答案**：`mmap` 把文件或匿名区域映射到进程地址空间，应用可以像访问内存一样访问文件，内核按页加载并利用页缓存。多个进程映射同一文件时还可以共享页面，适合随机访问大文件、共享内存和零拷贝式处理。

映射并不保证数据已经持久化到磁盘，仍需考虑脏页、`msync`、`fsync` 和崩溃一致性。文件被截断、映射范围错误或并发修改也可能导致异常，因此要明确生命周期和边界。

### 30. 栈和堆有什么区别？

**面试问法**：局部变量为什么通常在栈上，动态对象为什么在堆上？

**参考答案**：栈由调用约定自动管理，保存函数帧、返回地址和局部变量，分配释放快但空间有限且生命周期通常随调用结束。堆用于动态分配对象，生命周期由手动释放或垃圾回收管理，灵活但存在分配、碎片和同步成本。

“对象一定在堆上”不是跨语言的绝对规则，编译器可能做逃逸分析和栈上分配。工程排查时更应关注栈溢出、堆增长、分配热点和对象生命周期，而不是只背概念。

### 31. 内部碎片和外部碎片是什么？

**面试问法**：明明还有很多空闲内存，为什么分配仍然失败？

**参考答案**：内部碎片是分配块内部没有被使用的空间，例如按固定大小对齐；外部碎片是空闲空间分散成许多小块，合计足够但无法满足大块连续分配。分页通过固定大小页面减少了外部碎片，但会带来页内浪费。

内存分配器会通过分级空闲链表、合并相邻块、分区和大对象专用路径降低碎片。长时间运行的服务要观察 RSS、虚拟地址空间、分配器缓存和实际活跃对象，避免把碎片误判为纯内存泄漏。

## 四、文件、I/O 与容器

### 32. 文件描述符是什么？

**面试问法**：为什么“打开太多文件”也会影响网络连接？

**参考答案**：文件描述符是进程内指向内核对象的整数句柄，文件、管道、Socket、设备等都可以通过它访问。进程有软硬限制，系统也有全局限制；连接、日志文件和管道泄漏都会消耗描述符。

排查时查看进程的 `ulimit`、`/proc/<pid>/fd`、连接状态和打开文件类型。提高上限只能缓解容量问题，仍要修复未关闭资源、连接池泄漏和异常路径没有清理的问题。

### 33. inode、目录项和文件名是什么关系？

**面试问法**：为什么删除文件后空间可能没有立即释放？

**参考答案**：inode 保存文件元数据和数据块位置，目录项把文件名映射到 inode。一个 inode 可以有多个硬链接，因此文件名和文件本体不是同一个概念。删除目录项只减少链接数，只有链接数为零且没有进程打开该文件时，数据块才会真正回收。

日志文件被删除但磁盘仍满，常见原因是进程仍持有打开的文件描述符。应重启或让进程重新打开日志，并检查是否有匿名临时文件或容器挂载占用空间。

### 34. 硬链接和软链接有什么区别？

**面试问法**：软链接断了，硬链接为什么还可能可用？

**参考答案**：硬链接是多个目录项指向同一个 inode，删除其中一个名字不会删除数据，只要仍有其他链接或打开描述符；通常不能跨文件系统，也不能直接链接目录。软链接是一个保存目标路径的特殊文件，目标移动或删除后会失效，可以跨文件系统。

部署中使用软链接切换版本很方便，但要注意原子重命名、相对路径和正在运行进程是否已经打开旧文件。硬链接更适合需要共享同一 inode 的场景。

### 35. 文件系统日志有什么作用？

**面试问法**：突然断电后，日志文件系统如何减少损坏？

**参考答案**：日志文件系统先把元数据或部分数据变更写入日志，再提交正式位置，崩溃恢复时可以重放或回滚未完成操作，减少文件系统结构不一致。日志并不等于业务数据已经安全落盘，也不保证应用层事务自动恢复。

需要持久化时，应用还要合理使用 `fsync`、目录同步和原子替换。不同挂载选项、磁盘缓存和 RAID 控制器都会影响实际持久性，不能只看到“写入成功”就认为断电不丢。

### 36. `fsync` 为什么重要又可能很慢？

**面试问法**：写文件返回成功后，数据一定在磁盘上吗？

**参考答案**：普通写入成功通常只表示数据进入内核页缓存或设备队列，不代表已经持久化。`fsync` 请求内核把文件相关脏数据和元数据刷到稳定存储，因此能缩短崩溃丢失窗口，但会等待设备完成，延迟可能显著增加。

高性能服务会批量提交、使用日志结构、异步刷盘或把持久性要求分级。更新文件后再原子重命名时，还要根据文件系统语义同步目录，确保新名字本身不会因断电丢失。

### 37. 缓冲 I/O 和直接 I/O 有什么差别？

**面试问法**：为什么标准库和操作系统都要做缓存？

**参考答案**：缓冲 I/O 通过用户态和内核页缓存合并小写入、预读和缓存热点，减少系统调用和设备访问，适合多数应用。直接 I/O 尝试绕过页缓存，让应用自己管理对齐、缓存和并发，适合数据库等已经有专用缓存的系统。

直接 I/O 对地址、长度和磁盘对齐有要求，使用不当会让性能更差。选择时要避免重复缓存和内存压力，并用真实 workload 比较吞吐、延迟和尾延迟。

### 38. `select`、`poll` 和 `epoll` 有什么区别？

**面试问法**：高并发网络服务为什么常用 epoll？

**参考答案**：`select` 使用固定大小位图传入和返回就绪描述符，调用时需要遍历；`poll` 使用数组，去掉了固定位数限制，但仍需每次扫描；`epoll` 在内核中维护兴趣列表和就绪队列，应用可以获取就绪事件，连接很多但活跃连接较少时效率更好。

epoll 也不是自动更快。事件模式、惊群、读写循环、非阻塞语义和连接管理都影响性能。应用必须持续读完可读数据、处理 `EAGAIN`，并正确注销关闭的描述符。

### 39. 阻塞 I/O 和非阻塞 I/O 有什么区别？

**面试问法**：非阻塞 Socket 返回 `EAGAIN` 时怎么办？

**参考答案**：阻塞 I/O 在数据未准备好时让线程睡眠，代码简单但一个线程可能被一个连接占住；非阻塞 I/O 立即返回，应用通过事件通知等待可读或可写，再继续操作。高并发事件循环通常使用非阻塞模式。

`EAGAIN` 不是失败，而是当前没有更多数据或发送缓冲区暂时满。正确处理方式是保存未完成状态，等待下一次事件；不能在循环里无休止忙轮询，否则会耗尽 CPU。

### 40. 事件循环如何实现高并发？

**面试问法**：一个线程为什么能同时处理很多连接？

**参考答案**：事件循环把 Socket 设置为非阻塞，向内核注册感兴趣的读写事件，调用 `epoll_wait` 等待就绪。事件到达后，循环执行对应回调或协程，任务在等待 I/O 时让出执行权，因此一个线程可以管理大量连接。

事件循环不能运行长时间 CPU 计算或同步阻塞调用，否则所有连接都会被拖住。需要把阻塞 SDK 放到线程池，把重 CPU 工作放到进程池，并对任务设置取消、超时和背压。

### 41. Linux load average 表示什么？

**面试问法**：load average 高是不是就等于 CPU 使用率高？

**参考答案**：load average 统计一段时间内处于可运行状态或不可中断等待状态的任务数量，常见不可中断等待包括磁盘 I/O。它不只反映正在使用 CPU 的任务，因此高 load 可能来自 CPU 饱和、存储阻塞或内核等待。

要结合 CPU 利用率、iowait、运行队列、上下文切换、磁盘延迟和进程状态判断。对多核机器，load 是否“高”还要与 CPU 核数和服务目标比较，不能只看一个绝对数字。

### 42. cgroups 解决什么问题？

**面试问法**：容器如何限制 CPU 和内存？

**参考答案**：cgroups 把进程分组并限制或统计 CPU、内存、I/O、进程数等资源。容器运行时通过 cgroups 设置配额、权重和限制，使一个服务不能无限抢占宿主机资源，并能产生使用指标。

CPU 限制可能造成节流和尾延迟，内存达到上限可能触发 OOM kill。排查容器变慢时要同时看应用指标和 cgroup 的 `memory.current`、限制、CPU throttling 及进程数，而不是只看宿主机剩余资源。

### 43. Linux namespace 做什么？

**面试问法**：容器为什么能看到独立的进程和网络？

**参考答案**：namespace 为进程提供隔离视图，包括 PID、网络、挂载、UTS、IPC、用户等。进程在自己的 namespace 中看到的主机名、进程号、接口和挂载点可能与宿主机不同。

namespace 是视图隔离，不等于完整虚拟机隔离。容器仍共享宿主机内核，必须结合 capabilities、seccomp、只读文件系统、资源限制和最小权限来降低逃逸和误操作风险。

### 44. 容器和虚拟机有什么区别？

**面试问法**：为什么容器启动更快？隔离性是否相同？

**参考答案**：虚拟机通过 hypervisor 虚拟出硬件并运行独立内核，隔离边界强、系统开销较大；容器通过 namespace、cgroups 和镜像在宿主机内核上隔离进程，启动快、密度高，但共享内核。

容器适合服务打包、弹性扩缩和一致性部署，虚拟机适合不同内核、强隔离和完整操作系统需求。安全敏感场景可以使用虚拟机、沙箱或微虚拟机增强边界，而不是把容器默认当成安全边界终点。

### 45. 工具执行沙箱需要哪些操作系统能力？

**面试问法**：Agent 运行用户代码时如何限制风险？

**参考答案**：沙箱通常结合独立 namespace、cgroups、最小 capabilities、seccomp 系统调用过滤、只读根文件系统、临时工作目录、网络策略和严格的超时/进程数限制。输入输出也要通过受控管道传递，并记录审计事件。

“不能访问某个目录”需要同时检查挂载、用户权限、符号链接、设备文件和进程能力；“不能联网”也要覆盖 DNS、IPv6、代理和已有连接。沙箱设计要按攻击面测试，而不是只在代码里删除几个危险命令。

## 五、可靠性与系统设计

### 46. OOM killer 为什么会终止某个进程？

**面试问法**：内存不足时 Linux 如何选择牺牲者？

**参考答案**：当系统或 cgroup 无法满足内存分配时，内核会根据进程内存占用、优先级和调整值等因素选择进程终止，以恢复可用内存。被杀进程通常能在内核日志和容器事件中找到记录。

应先区分真实泄漏、缓存增长、瞬时峰值、页缓存和容器限制过小。增加限制只是缓解，仍需设置队列上限、流式处理、对象生命周期和降级策略，避免 OOM 后服务反复重启。

### 47. 异步程序为什么也会死锁？

**面试问法**：单线程事件循环没有线程竞争，为什么仍可能卡死？

**参考答案**：协程在 `await` 处交错执行，多个协程仍可能对共享状态执行非原子复合操作；如果持有异步锁后等待另一个永远不会完成的任务，也会形成等待环。同步阻塞调用还会让整个事件循环无法推进，看起来像死锁。

解决方式是缩短锁范围、统一获取顺序、避免持锁 `await` 外部不确定操作、为等待设置超时，并用任务转储查看每个协程卡在哪里。单线程只消除了同时运行，不会自动消除逻辑竞态。

### 48. 线程池和进程池如何设置大小？

**面试问法**：线程池是不是越大吞吐越高？

**参考答案**：I/O 线程池可以比 CPU 核数大一些，因为线程大部分时间在等待，但过大仍会造成上下文切换、连接池争用和下游过载。CPU 进程池通常接近可用核心数，再根据任务内存和调度开销调整。

池大小应与队列长度、下游并发限制、请求截止时间和机器配额一起设计。监控活跃数、排队时间、执行时间、拒绝数和取消数，才能判断是池太小还是下游已经成为瓶颈。

### 49. 服务如何实现优雅关闭？

**面试问法**：发布时如何避免正在执行的请求被直接杀掉？

**参考答案**：收到 SIGTERM 后，服务先停止接收新流量或从负载均衡摘除，再让现有请求在截止时间内完成，停止接收新任务，取消或转移排队任务，关闭连接池和线程/进程池，最后退出。无法在期限内完成的任务要有可恢复的状态和幂等重试。

流式连接需要发送结束事件或允许客户端识别断开，后台任务则要有检查点。优雅关闭不是无限等待，必须设置最大宽限期，并在超时后强制终止和记录未完成任务。

### 50. 如何从操作系统角度设计一个稳定的 Agent 服务？

**面试问法**：Agent 服务在进程、线程、内存和 I/O 层面如何保证稳定？

**参考答案**：网络层使用事件循环和连接池，阻塞 SDK 放在线程池，重 CPU 工作放进程池；每个请求有截止时间、取消传播和资源配额。上下文和工具输出采用流式或分块处理，避免把无界数据一次性读入内存；工作流状态保存检查点，进程重启后可以恢复或安全重试。

部署层使用 cgroups 限制 CPU、内存、文件描述符和进程数，容器采用最小权限和网络隔离；运行时监控 RSS、缺页、CPU throttling、I/O 延迟、线程池排队、连接数和 OOM 事件。面试回答的重点是把“能跑”扩展成资源边界、故障恢复和可观测性。
