# 15.3 数据结构

> 本节整理 50 道面向后端、算法和 Agent 开发岗位的高频数据结构题。回答时要同时说明数据结构的抽象、典型操作复杂度、适用场景和边界条件。复杂度是判断工具，不是脱离数据规模和访问模式的口号。

## 一、复杂度与线性结构

### 1. 如何分析时间复杂度和空间复杂度？

**面试问法**：一个算法的 O(n) 代表什么？为什么常数有时也重要？

**参考答案**：时间复杂度描述输入规模增长时，操作次数如何增长；空间复杂度描述额外使用的内存如何增长。大 O 关注渐近上界，忽略常数和低阶项，例如遍历数组是 O(n)，嵌套两层独立遍历通常是 O(n²)。

实际工程不能只看 O 表示法。缓存命中、内存局部性、对象分配、网络和磁盘 I/O 都可能让常数项成为主要成本。面试中应先给渐近复杂度，再说明数据规模、最坏情况和实际瓶颈。

### 2. 数组和链表有什么区别？

**面试问法**：为什么数组按下标访问快，链表插入删除可能快？

**参考答案**：数组元素通常连续存放，可以通过首地址和下标直接计算位置，随机访问是 O(1)，但中间插入删除需要搬移元素。链表节点通过指针连接，按位置查找是 O(n)，如果已经拿到目标节点及其前驱，插入删除可以是 O(1)。

现代硬件下数组通常还有更好的缓存局部性，实际性能经常优于指针跳转的链表。Python 的 `list` 是动态数组，`collections.deque` 更适合两端进出，不能把抽象复杂度直接等同于某个语言容器的全部性能。

### 3. 动态数组是如何扩容的？

**面试问法**：为什么动态数组的 `append` 平均是 O(1)？

**参考答案**：动态数组会预留比当前元素更多的容量，尾部有空位时直接写入；容量不足时申请更大内存并批量搬迁元素。单次扩容可能是 O(n)，但扩容后容量通常按比例增长，因此连续追加 n 个元素的总搬迁成本是 O(n)，摊销到每次追加得到 O(1)。

扩容比例影响内存浪费和扩容次数。提前知道数据量时预分配或批量构造可以减少搬迁；频繁在头部插入则不适合动态数组，应考虑队列或双端队列。

### 4. 单链表和双链表怎么选？

**面试问法**：双链表多一个前驱指针，值不值得？

**参考答案**：单链表每个节点只保存后继指针，内存更省，实现更简单；双链表额外保存前驱指针，可以在已知节点时 O(1) 地向前移动和删除，适合需要双向遍历或频繁摘链的场景。两者按值查找都通常是 O(n)。

LRU 缓存常用哈希表加双链表：哈希表把 key 定位到节点，双链表维护新旧顺序，读写和淘汰都能达到平均 O(1)。实现时要重点处理头尾哨兵、空链表和重复移动。

### 5. 栈和队列有什么区别？

**面试问法**：栈和队列分别适合什么问题？

**参考答案**：栈遵循后进先出，常用于函数调用、括号匹配、深度优先搜索和撤销操作；队列遵循先进先出，常用于任务调度、广度优先搜索和生产者消费者模型。它们的核心差异是取出元素的顺序，而不是底层必须使用哪种容器。

用数组实现栈时尾部追加和弹出通常是 O(1)；用链表也可以。队列若用数组从头部删除会反复搬移元素，应使用环形缓冲区、双端队列或两个栈实现。

### 6. 如何用两个栈实现队列？

**面试问法**：入队和出队分别怎么做，摊销复杂度是多少？

**参考答案**：一个栈负责接收入队元素，另一个栈负责出队。如果出队栈为空，就把入队栈中的元素逐个弹出并压入出队栈，顺序会被反转，最早进入的元素位于顶部。之后的出队直接从出队栈弹出。

单次转移可能是 O(n)，但每个元素最多从一个栈移动到另一个栈一次，因此连续操作的摊销复杂度是 O(1)。面试时要说明“最坏单次”和“摊销平均”不是同一个概念。

### 7. `deque` 和普通列表有什么差别？

**面试问法**：为什么队列通常不用列表的 `pop(0)`？

**参考答案**：列表头部删除需要把后面的元素整体前移，复杂度通常是 O(n)；双端队列在两端插入和删除都能稳定做到 O(1) 左右，适合滑动窗口、BFS 和任务队列。列表更适合随机访问和尾部追加。

在 Python 中可以使用 `collections.deque`，并根据访问模式选择 `append`、`popleft` 或 `appendleft`。如果需要按优先级取最小值，应使用堆，而不是把 deque 当成优先队列。

### 8. 哈希表为什么平均查找是 O(1)？

**面试问法**：字典是怎么根据 key 找到 value 的？

**参考答案**：哈希表先对 key 计算哈希值，再把哈希值映射到桶或槽位。理想情况下不同 key 分布均匀，查找只需检查少量位置，因此平均是 O(1)。key 必须满足哈希稳定、相等对象哈希相同等约束。

最坏情况下大量 key 发生冲突，查找可能退化为 O(n)，所以实现需要扩容、优秀的哈希函数和冲突处理。Python 的 `dict` 还保持插入顺序，但顺序语义不等于它变成了树或排序结构。

### 9. 哈希冲突有哪些解决方法？

**面试问法**：两个 key 映射到同一个桶时怎么办？

**参考答案**：常见方法是开放定址法和链地址法。开放定址法在表内寻找其他空槽，可以使用线性探测、二次探测或双重哈希；链地址法在每个桶上挂一个链表或其他容器保存冲突项。

开放定址法要关注装载因子和删除标记，链地址法要关注额外指针和内存局部性。无论使用哪种方法，扩容都需要重新分布已有 key，因为桶数量改变后原来的位置通常不再适用。

### 10. 装载因子为什么会影响哈希表性能？

**面试问法**：为什么哈希表不能一直装到满？

**参考答案**：装载因子是元素数量与桶数量的比值。因子越高，冲突概率和探测长度通常越大，查找、插入会逐渐变慢；开放定址法接近装满时尤其明显。因此实现会在达到阈值时扩容，并重新计算位置。

扩容会带来一次 O(n) 成本，但和动态数组一样，可以通过摊销分析得到较好的平均性能。实际阈值取决于冲突策略、内存预算和缓存局部性，不能脱离实现简单背一个固定数字。

### 11. 哈希表、平衡树和跳表如何选？

**面试问法**：需要有序遍历时为什么不能只用哈希表？

**参考答案**：哈希表平均查找、插入和删除快，但不天然支持按 key 排序、范围查询和前驱后继。平衡搜索树通常在 O(log n) 内提供有序操作；跳表通过多层索引实现类似的期望复杂度，结构更容易并发化。

只做精确查找时哈希表通常合适；需要范围扫描、最小最大值或顺序迭代时选择树或跳表。数据库索引常用 B+ 树，因为它能把有序范围访问和磁盘页布局结合起来。

## 二、树、堆与索引结构

### 12. 树中的高度、深度和度分别是什么？

**面试问法**：树的高度和节点深度怎么区分？

**参考答案**：节点深度通常指从根到该节点的边数，根的深度为零；节点高度通常指从该节点到最深叶子的边数，叶子高度为零；一棵树的高度是根节点高度。节点的度是它拥有的直接子节点数量。

不同教材可能把根的高度或深度按节点数计数，因此面试回答时要说明采用的定义。清晰定义比死记某个数字更重要，因为复杂度分析依赖的是树高是否接近 log n。

### 13. 二叉搜索树的性质是什么？

**面试问法**：为什么二叉搜索树可以做快速查找？退化时会怎样？

**参考答案**：对每个节点，左子树的 key 小于节点，右子树的 key 大于节点，重复值需要由实现规定放置策略。沿比较结果向左或向右走，查找、插入和删除的时间与树高成正比。

如果插入数据已经有序，普通二叉搜索树会退化成链表，高度变为 O(n)，操作也退化为 O(n)。因此需要随机化、AVL、红黑树或其他平衡策略控制高度。

### 14. AVL 树和红黑树有什么区别？

**面试问法**：为什么工程里常见红黑树，而不是总用 AVL？

**参考答案**：AVL 对左右子树高度差限制更严格，查找路径更短，但插入和删除时可能需要更多旋转。红黑树通过颜色和路径约束保证树高是 O(log n)，平衡较宽松，更新通常更少旋转。

读多写少、非常关注查找路径时 AVL 可能有优势；更新频繁、希望实现稳定且综合性能好时常用红黑树。两者都提供有序操作，选择还要考虑库实现、内存布局和并发需求。

### 15. 旋转在平衡树中解决什么问题？

**面试问法**：左旋和右旋会不会破坏搜索树顺序？

**参考答案**：旋转通过局部改变父子关系降低某一侧的高度，同时保持中序遍历结果不变，因此不会破坏二叉搜索树的有序性。左旋通常把右孩子提升，右旋把左孩子提升，具体方向取决于失衡形态。

实现旋转时最容易出错的是父指针、根节点更新和子树转移。面试不一定要求完整手写全部代码，但应能说明旋转只改变局部链接，并保持每个节点的搜索顺序不变。

### 16. 堆是什么？

**面试问法**：最小堆和二叉搜索树有什么区别？

**参考答案**：最小堆只保证每个父节点不大于子节点，因此根是全局最小值；它不保证左右子树之间的顺序。完全二叉树通常用数组存储，节点下标可以通过公式找到父子节点，避免显式指针。

堆顶查看是 O(1)，插入和删除堆顶是 O(log n)，建堆可以通过自底向上调整在 O(n) 完成。若需要任意 key 的有序查找，堆不如搜索树；若只需不断取得最小或最大值，堆更合适。

### 17. 优先队列如何实现？

**面试问法**：任务按优先级处理，用什么数据结构？

**参考答案**：优先队列通常用二叉堆实现，每次取出最高优先级元素，再把新任务上浮或下沉到正确位置。Python 中可使用 `heapq`，通过存储 `(priority, sequence, item)` 处理相同优先级的稳定顺序。

优先级更新和删除任意元素在基础堆里不够直接，常用“延迟删除”：给任务增加版本号或失效标记，弹出时跳过过期节点。如果需要高效 decrease-key 或大量合并，可以考虑更专门的堆结构。

### 18. Trie 树适合解决什么问题？

**面试问法**：自动补全和前缀搜索为什么常用 Trie？

**参考答案**：Trie 按字符或 token 的路径组织字符串，查找、插入和前缀判断的复杂度与 key 长度相关，而不是与 key 数量直接相关。节点可以保存是否为完整单词、频次和候选结果。

Trie 的代价是节点多、指针开销大，字符集大时需要压缩边或使用数组与哈希表混合。搜索建议通常还要限制候选数量、缓存热门前缀，并在更新时考虑并发和内存回收。

### 19. B 树和 B+ 树为什么适合数据库索引？

**面试问法**：数据库索引为什么不用普通二叉树？

**参考答案**：磁盘或 SSD 访问按页进行，B 树和 B+ 树每个节点可以容纳大量 key，树高很低，一次读取一个页就能排除大范围数据。B+ 树把记录指针集中在叶子节点，并把叶子按顺序链接，适合范围扫描。

索引不是越多越好。写入时要更新索引页，查询时要付出维护和存储成本；联合索引的列顺序、选择性和回表次数会直接影响效果。面试中可以把数据结构优势和存储设备的 I/O 模型联系起来。

## 三、图与经典算法

### 20. 图的顶点、边、路径和连通性分别是什么？

**面试问法**：有向图和无向图在建模上有什么不同？

**参考答案**：图由顶点和边组成，边可以有方向和权重。路径是沿边从一个顶点到另一个顶点的序列，若路径回到起点或包含重复顶点边，可能形成环。无向图的边没有方向，有向图的边表示单向关系。

网络依赖、工作流和权限继承都可以建模为图。开始算法前要明确边是否有向、是否有权、是否允许重复边，以及需要的是可达性、最短路、排序还是连通分量。

### 21. 邻接矩阵和邻接表如何选择？

**面试问法**：稠密图和稀疏图分别适合什么表示？

**参考答案**：邻接矩阵用二维数组表示任意两点是否相连，判断一条边是 O(1)，但空间是 O(V²)，适合顶点少或边很密的图。邻接表只保存实际存在的边，空间是 O(V+E)，遍历某个顶点的邻居更高效，适合大多数稀疏图。

如果算法频繁判断任意两点是否相连，矩阵可能更直接；如果图规模大、边远少于 V²，邻接表更省内存。工程中还要考虑权重、边属性、缓存局部性和动态增删。

### 22. BFS 和 DFS 有什么区别？

**面试问法**：什么时候用广度优先，什么时候用深度优先？

**参考答案**：BFS 使用队列按层扩展，适合无权图的最短边数路径、层级遍历和最少步骤问题；DFS 使用栈或递归沿一条路径深入，适合连通分量、拓扑排序、回溯和环检测。

两者遍历整张图的时间都可以是 O(V+E)，区别在于访问顺序和辅助空间。递归 DFS 可能受调用栈深度限制，生产代码处理大图时常改用显式栈，并用 visited 集合避免重复访问。

### 23. BFS 为什么能求无权图最短路？

**面试问法**：从起点到终点的最少边数怎么求？

**参考答案**：BFS 先访问距离为 0 的起点，再访问距离为 1、2 的节点，队列保证节点第一次出队时已经是最短距离。为每个节点记录前驱，就能在到达终点后反向恢复完整路径。

如果边有不同权重，按层推进就不再保证最短，应改用 Dijkstra、0-1 BFS 或 Bellman-Ford。即使图无权，也要明确是否存在重复边、自环和不可达节点。

### 24. DFS 的递归和迭代写法有什么差别？

**面试问法**：递归 DFS 可能有哪些工程问题？

**参考答案**：递归写法直观，调用栈天然保存当前路径和返回位置；迭代写法用显式栈，更容易控制内存并避免递归深度限制。两者逻辑上都要在合适时机标记 visited，防止有环图无限循环。

需要记录后序顺序或路径状态时，显式栈可能要把“节点、下一个待处理邻居、当前状态”一起压入。面试中应说明递归的空间复杂度包含调用栈，不要只计算图上的 visited 集合。

### 25. 什么是拓扑排序？

**面试问法**：任务依赖如何排出可执行顺序？

**参考答案**：拓扑排序用于有向无环图，把每条边 `u → v` 的前驱 u 排在 v 之前。Kahn 算法不断取入度为零的节点并删除其出边；DFS 则按完成时间逆序输出。

如果处理完的节点数少于总节点数，说明图中存在环，没有合法拓扑序。项目编译、工作流编排和任务依赖都可以使用拓扑排序，实际还要处理并行执行、失败重试和动态依赖。

### 26. 如何判断有向图和无向图是否有环？

**面试问法**：为什么有向图需要“当前路径”标记？

**参考答案**：无向图 DFS 中，如果访问到已访问节点且它不是当前节点的父节点，就说明存在环；并查集也可以在线性遍历边时判断无向环。对于有向图，仅有 visited 不够，因为一条边指向已经完成的节点不一定形成环。

有向图通常使用三色标记：未访问、正在当前递归路径中、已完成。遇到指向“正在访问”节点的边就是回边，说明存在环。Kahn 算法通过拓扑排序剩余节点数也能检测有向环。

### 27. Dijkstra 算法的前提是什么？

**面试问法**：为什么 Dijkstra 不能处理负权边？

**参考答案**：Dijkstra 适用于边权非负的图。它每次从未确定节点中取出当前距离最小者，并认为该距离已经最优，因为之后再经过非负边不可能变得更小，随后松弛它的邻边。

如果存在负权边，这个贪心结论可能被后续路径推翻。实现通常用优先队列，堆中允许同一节点出现多个旧距离，弹出时若不是最新距离就跳过。复杂度取决于图表示和堆实现，常见写法是 O((V+E) log V)。

### 28. Bellman-Ford 什么时候更合适？

**面试问法**：有负权边甚至负环时如何求最短路？

**参考答案**：Bellman-Ford 对所有边进行最多 V-1 轮松弛，可以处理负权边；再进行一轮如果仍有距离更新，就说明从起点可达的区域存在负权环。它的复杂度通常是 O(VE)，比 Dijkstra 慢，但适用范围更广。

实际系统中负权常代表收益、折扣或成本变换，使用前要确认模型是否允许无限降低的负环。若只需要检测负环而不需要完整距离，也可以在实现上提前停止或使用其他图算法。

### 29. Floyd-Warshall 适合什么场景？

**面试问法**：如何求所有点对之间的最短路？

**参考答案**：Floyd-Warshall 使用动态规划，逐步允许中间节点集合扩大，状态表示当前点对在允许某些中间点时的最短距离。三重循环复杂度 O(V³)，空间 O(V²)。

它适合顶点数较少、需要所有点对结果的稠密图。顶点很多或只关心单源最短路时，应选择 Dijkstra、Bellman-Ford 或多次 BFS，并注意初始化无边、对角线和负环。

### 30. 最小生成树是什么？

**面试问法**：Kruskal 和 Prim 有什么区别？

**参考答案**：在连通无向带权图中，最小生成树连接所有顶点且总权重最小，并且不包含环。Kruskal 按边权从小到大处理边，用并查集判断加入后是否成环；Prim 从一个顶点出发，每次选择连接已选集合的最小边。

Kruskal 更自然地按边排序，适合边相对较少的图；Prim 适合使用邻接表和优先队列逐步扩张。两者都要求图的建模与边权含义正确，最小生成树解决的是连通成本，不是任意两点最短路。

### 31. 并查集解决什么问题？

**面试问法**：如何快速判断两个节点是否属于同一集合？

**参考答案**：并查集维护若干不相交集合，支持 `find` 查询代表元和 `union` 合并集合。路径压缩会把查找路径直接连到根，按秩或按大小合并让树保持较浅，连续操作的摊销复杂度接近常数。

它适合网络连通性、Kruskal、动态分组和等价关系合并。并查集不擅长删除边、查询具体路径或维护复杂的有序信息，这些需求需要更专门的数据结构。

## 四、排序、查找与常用技巧

### 32. 稳定排序是什么意思？

**面试问法**：排序稳定性什么时候有用？

**参考答案**：稳定排序保证两个 key 相等的元素在排序后仍保持原有相对顺序。例如先按创建时间排序，再稳定地按优先级排序，就能保留同优先级任务的时间顺序。

稳定性是排序算法和实现的属性，不是所有排序天然都有。归并排序通常稳定，快速排序和堆排序的常见原地实现通常不稳定。多关键字排序、分页和日志展示中要明确是否依赖稳定性。

### 33. 快速排序为什么平均是 O(n log n)？

**面试问法**：快速排序最坏为什么会退化？如何改进？

**参考答案**：快速排序围绕 pivot 分区，平均情况下每次把数据分成相对均衡的两部分，递归深度约为 log n，每层处理 n 个元素，因此平均 O(n log n)。如果每次 pivot 都是最小或最大值，分区会极不均衡，退化为 O(n²)。

随机选择 pivot、三数取中、三向分区和递归深度保护都能降低退化概率。它通常具有较好的缓存局部性和较小的额外空间，但需要处理重复元素和栈深度。

### 34. 归并排序有什么特点？

**面试问法**：为什么归并排序适合链表和外部排序？

**参考答案**：归并排序把序列分成两半，分别排序后线性合并，时间复杂度稳定为 O(n log n)。数组实现通常需要 O(n) 辅助空间，但链表可以通过调整指针完成合并，避免大量搬移。

归并排序稳定、访问模式顺序，适合外部排序：把大文件分块排序后，再多路归并。代价是额外空间和写入次数，内存内排序时要结合数据规模和稳定性需求选择。

### 35. 堆排序有什么优缺点？

**面试问法**：堆排序为什么能保证 O(n log n)？

**参考答案**：先把数组建成最大堆，再反复把堆顶交换到末尾并恢复堆结构。建堆 O(n)，每次调整 O(log n)，总复杂度 O(n log n)，最坏情况也有保证，且可以原地排序。

堆排序通常不稳定，缓存局部性也可能不如快速排序。它适合需要严格最坏复杂度和低额外空间的场景，但工程中常用的库排序可能采用混合算法，综合了快速、堆和插入排序的优点。

### 36. 计数排序和基数排序什么时候用？

**面试问法**：非比较排序为什么可以突破 O(n log n)？

**参考答案**：计数排序利用 key 范围有限这一条件，统计每个值出现次数，再按顺序输出，复杂度与 n 加值域大小有关。基数排序把整数或字符串按位分组，多轮使用稳定的低位排序。

它们不是无条件快。值域过大、数据分布稀疏或 key 长度很长时，计数数组和多轮处理的成本可能超过比较排序。选择前要明确 key 类型、范围、内存和是否需要稳定性。

### 37. 二分查找的循环不变量是什么？

**面试问法**：为什么二分查找经常出现边界错误？

**参考答案**：二分查找的核心是明确区间定义，例如使用左闭右闭区间 `[left, right]`，并保证答案始终位于该区间。每次比较后缩小区间，循环结束时再根据不变量判断是否找到目标或插入位置。

“找任意等于目标”“找第一个大于等于目标”“找最后一个小于等于目标”是不同问题，不能只改一个比较符号。建议先写出区间含义和循环终止条件，再实现 `mid` 计算，避免空区间和整数溢出。

### 38. 双指针适合解决什么问题？

**面试问法**：有序数组两数之和为什么能用左右指针？

**参考答案**：双指针利用单调性减少重复搜索。对有序数组，左指针和右指针的和太小就增大左指针，太大就减小右指针，每个指针最多移动 n 次，因此是 O(n)。

同向双指针常用于原地去重、快慢指针和区间扫描；相向双指针常用于两数之和、回文和容器问题。无序数据若没有单调性，通常需要哈希表或先排序，这会改变复杂度和稳定性。

### 39. 滑动窗口和双指针有什么关系？

**面试问法**：如何求最长不含重复字符的子串？

**参考答案**：滑动窗口维护一个满足条件的连续区间，右指针扩展窗口，条件被破坏时移动左指针恢复合法。每个元素最多进入和离开窗口一次，通常能把 O(n²) 的枚举降为 O(n)。

窗口中要维护什么状态取决于问题，可以是计数器、集合、哈希位置或当前和。关键是证明左指针不会后退，并在更新答案前明确当前窗口是否已经合法。

### 40. 前缀和和差分数组分别解决什么问题？

**面试问法**：大量区间求和或区间加法怎么优化？

**参考答案**：前缀和把前 i 个元素的累积结果保存下来，任意静态区间和可以用两个前缀值相减在 O(1) 得到，构建成本 O(n)。差分数组记录相邻元素的变化，区间加法只需修改边界两个位置，最后做一次前缀累加恢复数组。

这两种技巧都把“每次查询或更新的成本”转移到预处理或最终重建。若查询和更新交错且都很多，需要 Fenwick 树或线段树等动态结构。

### 41. 单调栈解决什么问题？

**面试问法**：如何求每个元素右侧第一个更大元素？

**参考答案**：单调栈保持栈内元素按某种单调关系排列。遍历到新元素时，不满足单调性的栈顶元素可以确定答案并弹出；每个元素最多入栈和出栈一次，所以总复杂度 O(n)。

它适合下一个更大元素、柱状图最大矩形、每日温度等问题。要先明确栈中存的是下标还是值，因为很多题需要计算距离、宽度或处理重复值。

### 42. 单调队列解决什么问题？

**面试问法**：如何在线性时间求滑动窗口最大值？

**参考答案**：单调队列维护候选下标，使队列对应的值保持递减，队首就是当前窗口最大值。新元素进入时，从队尾删除不可能成为未来最大值的较小元素；窗口左边界右移时，过期下标从队首删除。

每个下标最多入队和出队一次，因此整体 O(n)，空间 O(k)。队列中保存下标而不是值，才能判断元素是否已经离开窗口，并正确处理重复值。

## 五、工程化数据结构

### 43. 递归、回溯和动态规划有什么区别？

**面试问法**：为什么有些递归题需要记忆化？

**参考答案**：递归是用函数调用表达问题分解，回溯是在递归基础上尝试选择、深入、撤销，常用于排列组合和约束搜索。动态规划利用子问题重叠和最优子结构保存中间结果，避免重复计算。

记忆化递归是自顶向下的动态规划，表格 DP 是自底向上的实现。判断能否使用 DP，要明确状态、转移、初始条件和遍历顺序，而不是看到递归就盲目加缓存。

### 44. LRU 缓存如何做到平均 O(1)？

**面试问法**：请设计一个支持 get 和 put 的 LRU。

**参考答案**：哈希表负责根据 key 找到节点，双向链表维护访问顺序，链表头表示最近使用，尾部表示最久未使用。读取或更新节点时把它移动到头部，容量超限时删除尾部节点。两种结构组合后，定位和调整都能平均 O(1)。

实现要处理重复 put、容量为零、删除头尾节点和并发访问。生产环境还要决定缓存的是值还是共享引用、是否设置过期时间、是否统计命中率，以及淘汰时是否允许瞬时抖动。

### 45. LFU 和 LRU 有什么区别？

**面试问法**：访问频率和最近访问时间冲突时怎么淘汰？

**参考答案**：LRU 淘汰最久没有访问的对象，适合时间局部性明显的场景；LFU 淘汰访问次数最少的对象，更偏向保留长期热门数据。LFU 还要定义频率相同的 tie-breaker，常用最近访问时间。

精确 LFU 需要维护 key 到节点、频率到双链表以及当前最小频率等结构，读写可以做到平均 O(1)，但实现更复杂。真实缓存还要考虑频率衰减，否则早期热点可能长期占据空间。

### 46. Bloom Filter 有什么用？

**面试问法**：如何快速判断一个 key 肯定不存在？

**参考答案**：Bloom Filter 用多个哈希函数把 key 映射到位数组。查询时只要有一个位为 0，就可以确定 key 不存在；如果所有位都为 1，只能说“可能存在”，因此存在误判但不会漏报不存在项。

它适合缓存穿透防护、去重和海量集合的存在性预筛选。误判率取决于位数组大小、哈希函数数量和插入元素量，标准 Bloom Filter 不支持简单删除，需要计数 Bloom Filter 或定期重建。

### 47. 跳表为什么适合做有序集合？

**面试问法**：跳表和红黑树如何比较？

**参考答案**：跳表在有序链表上增加多层随机索引，查找时从高层跳跃，再逐层下降，期望时间复杂度 O(log n)，插入和删除也能保持期望 O(log n)。它的实现比复杂平衡树更直观，范围遍历沿底层链表即可完成。

跳表的性能依赖随机层高和内存布局，最坏情况可能退化。Redis 的有序集合等系统使用跳表是因为它易于实现范围操作和并发读写，但具体选择仍需结合语言、内存和一致性需求。

### 48. 如何给数据结构加并发保护？

**面试问法**：线程安全的队列和普通队列有什么差别？

**参考答案**：并发安全不仅是把每个方法包一把锁，还要保证复合操作的原子性，例如“检查容量后入队”不能被另一个线程插入打断。可以使用互斥锁、读写锁、条件变量、无锁算法或把状态外置到支持原子操作的存储。

`queue.Queue` 会处理多线程生产消费中的锁和等待；`collections.deque` 的单个操作在特定解释器中可能是原子的，但不应把这种实现细节当成完整的业务同步方案。异步代码也要保护跨协程的复合状态。

### 49. Agent 的上下文窗口该用什么数据结构管理？

**面试问法**：对话历史越来越长，如何保留重要信息并控制 token？

**参考答案**：可以把消息按时间组织成双端队列，用滑动窗口保留最近上下文；用哈希表按消息 ID 去重和定位；用优先队列或评分结构选择最值得保留的摘要、工具结果和用户约束。超过预算时，先按策略压缩或摘要，再淘汰低价值片段。

数据结构选择要服务于可解释的淘汰策略。应记录每次压缩的原因、保留的约束和 token 估算，避免简单按字符截断导致系统提示、权限信息或关键工具结果被误删。

### 50. 如何为 Agent 工作流设计图结构？

**面试问法**：一个多工具 Agent 的状态和执行顺序如何表示？

**参考答案**：可以用有向图表示节点和依赖，用邻接表保存出边，用入度或就绪队列调度可执行节点，用状态字典保存每个节点的输入、输出、重试次数和错误。拓扑排序适合固定 DAG，条件分支和循环则需要显式的状态转换与终止条件。

工程上还要给节点和边定义唯一 ID、幂等键、超时和取消语义，并把执行轨迹作为事件流保存。这样既能支持并行工具调用，也能在失败后从安全检查点恢复，而不是把整个工作流塞进一个不可观测的递归函数。
