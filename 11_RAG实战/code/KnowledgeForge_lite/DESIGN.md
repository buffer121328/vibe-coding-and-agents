# Design

<!-- impeccable:design-schema 1 -->

## World

**一套控制台，两处安装**。Lite 的界面语言不是另立门户，而是**完整版 KnowledgeForge 的
课堂版**：同一个深藏青侧边栏、同一顶白栏、同一块灰蓝画布、同一个主色 `#155eef`。
学生在这边学会的动作，搬到完整版上认得出位置——这是本产品迭代到这一版才定下的原则，
比"Lite 要有自己的样子"更重要。

顶栏放登录用户（账号决定"你是谁"）；**四张可点的工牌**待在问答区顶部那条对照条里。
账号是真的（注册/登录，服务端会话表），工牌是课堂上用来切身份看权限差的开关——两件事别混。

## Surfaces

- `/login` 登录 / 注册（`render_login_page`），Mode: Operate。
  居中一张 420px 卡片：KF 渐变方块 + 产品名 + 副标题 + 选项卡（登录 / 注册）+
  表单 + 整宽主按钮 + "以访客身份看看"。结构对着完整版 `pages/Login.tsx`。
- `/` 控制台（`render_chat_page`），Mode: Operate。三段壳层 + 三个视图
  （智能问答 / 知识文档 / 评测治理），侧边栏切换，不跳页。未登录会 303 到 `/login`。

**这是重设计**：上一版"受控档案室"（纸/墨/朱砂/宋体）整体退场，不是打磨。

是整套里唯一一处多色渐变——**只此一处**，别处再要渐变就是跑偏。

## Type

- **Inter**，回落到 `-apple-system / Segoe UI / PingFang SC / Microsoft YaHei`。
  和完整版 `index.css` 的 `font-family` 一字不差。
- 基准 14px，行高 1.5；标题 24/20/16/14，靠字重（650）而不是字号拉开层级。
- 数字一律 `tabular-nums`：登记号、切块数、耗时、命中率、页码。
- 正文行宽 ≤ 74ch（答案区），说明文案 ≤ 76ch。
- 代码与原文用 `inherit` 而不是等宽字体——这一版的文档正文是**制度文件**，
  等宽会把它变成代码块，那是上一版的语汇。

> ⚠️ 设计检测器会把 Inter 标成 `overused-font`。**这里不采纳**：
> 完整版的前端字体栈就是 Inter，Lite 换掉它就不是"同一个控制台"了。
> 检测器的这条警告针对的是"随手挑一个默认字体"，而这里是有明确依据的继承。

- **侧边栏 248px**（收起 80px）：品牌块、按组分节的导航、底部收起按钮。
  选中项是蓝色渐变胶囊 + 投影，和完整版 `.ant-menu-item-selected` 一致。
- **顶栏 72px**（`min-height`，工牌换行时会长）：左边面包屑（11px）压页面标题（15px 加粗），
  右边工牌架。用 `backdrop-filter: blur(14px)` + 半透明白。
- **内容区**：`padding: 28px`，内层 `width: min(100%, 1600px); margin: 0 auto`。
- **页面头**（`.page-head`）：46px 图标砖（浅蓝底 + 描边 + 12px 圆角）+ h2 + 说明，
  右侧是动作按钮组。这是完整版 `.enterprise-page-header` 的同款。

## Identity: 账号是身份，工牌是演示开关

完整版的身份链是「登录 → JWT → 角色 → 权限」。Lite 保持同一条链，只把 JWT 换成了
**服务端会话表**——不是偷懒，是这件事上更简单的做法恰好更安全：

| | 完整版 | Lite |
| :--- | :--- | :--- |
| 口令 | bcrypt 哈希 | ``pbkdf2_hmac`` 加盐迭代 20 万轮（标准库，不引依赖），比对用等时比较 |
| 会话 | JWT + 令牌黑名单 | 库里一行随机 token；**登出 = 删那一行**，立刻失效，不用维护黑名单 |
| Cookie | ``access_token`` + ``refresh_token`` | 一个 ``HttpOnly`` + ``SameSite=Lax`` 的会话 cookie |

**账号与工牌的分工**（这是 Lite 独有的，也是踩过一次才理清的）：

- **账号**（`accounts.sqlite`）决定"你是谁"：显示名、角色、部门。
  **顶栏右上角只放它**——身份在应用框架里只有一个位置。退出登录也在这里。
- **工牌**（`identity.USERS`）是**演示身份切换器**，只出现在 Lite 里——完整版没有这一块。
  它是课堂教具，所以待在**问答区顶部那条对照条**里，而不是待在顶栏上。

  踩过的坑：一开始工牌架放在顶栏，于是加完登录之后，`公司管理员 / 公司管理员 · 公司`
  在屏幕上出现了两次（一次在账号区、一次在选中的工牌上），并排。同一个事实有两个位置，
  读者第一反应是"哪个是对的"。现在的分工是：**顶栏回答"你是谁"，对照条回答"权限差多少"**。

- 登录时初始选中项由**账号的 ``badge_id``** 决定：身份来自账号，不是页面上的开关。
- **切工牌也切权限**：切到 IT 员工，知识文档和评测治理会一起锁上——
  这不是 bug，是"权限先于检索"这条纪律在演示模式下的自然结果。

**库建出来是空的，谁用谁注册。** 不预置账号是刻意的：默认口令的账号（哪怕只在文档里
写着）等于给系统留一把人人都知道的钥匙，而课堂又不需要它。

注册表单只有**一个下拉：四张工牌**。不拆成"角色 + 部门"两个的原因写在 `accounts.IDENTITIES`
的注释里——权限由 (角色, 部门) 这一对决定，而工牌空间只有四种组合，让用户自由拼 3×4 会
拼出 8 种查不到的组合，只能回落（曾经就把"公司管理员 + IT"回落成了 IT 员工）。
**表单拼不出的状态，后端就不用写防御。**

不想注册就点"以访客身份看看"，走演示模式（工牌随便切，会话不归谁）。

## Components

| 组件 | 语法 |
| :--- | :--- |
| 卡片（`.card`） | 白底、1px `--border-2`、12px 圆角、`0 1px 3px rgba(16,24,40,.06)` 一层浅影 |
| 统计卡（`.stat`） | 标签在上、28px 数字在下、可选脚注；hover 上浮 2px。一排 `auto-fit minmax(190px,1fr)` |
| 表格（`.grid`） | 表头 `#f9fafb` 底 + 12px `#344054` 字，行 hover `#f5f8ff`，末列右对齐 |
| 两行首列 | `.cell-name`（主名）+ `.cell-meta`（登记号/工牌/来源），完整版表格的同款组织 |
| 标签（`.tag`） | 22px 高、4px 圆角、1px 描边、12px 字。五种状态：ok / warn / bad / info / mute |
| 按钮（`.btn`） | 32px 高、8px 圆角；`is-primary` 实心蓝、`is-link` 蓝字链接、`is-danger` 红 |
| 选项卡（`.tab`） | 下划线式：选中蓝字 + 2px 蓝色底线 |
| 提示条（`.alert`） | 浅蓝底 + 蓝描边 + 图标；`is-warn` / `is-bad` 两个变体 |
| 抽屉（`.drawer`） | 右侧滑入 460px（窄屏 92vw），`Escape` 可关。分块、用例详情、报告都在这里 |
| 折叠（`.fold`） | 答案下方的"推理步骤 / 引用来源"，箭头随展开旋转 90° |
| 消息气泡（`.bubble`） | 用户：蓝底白字，靠右；助手：白底描边浅影，靠左。圆角 8px |
| 头像（`.turn-avatar`） | 36px 圆，用户蓝（人像图标）、助手紫（机器人图标） |
| 账号区（`.account`） | 顶栏右上：32px 圆头像 + 显示名 + 角色·部门，点开是退出登录 |
| 连体输入（`.composer`） | 输入框与发送键拼成一组，只在外侧两角留圆角 |
| 登录卡（`.auth-card`） | 420px 居中卡片；`.auth-brand` 是 KF 渐变方块 + 产品名 + 副标题 |
| 对照条（`.identity-bar`） | 白底、一行、四张工牌胶囊；选中那张蓝边加浅蓝底 |

**图标**是一套手写的 24 栅格描边 SVG（`stroke-width: 1.7`，`currentColor`），
定义在 `web/pages.py` 的 `_ICONS` 里，作为 `<symbol>` 渲染一次；服务端用 `<use>` 引用，
JS 用 `ico()` 造同一个引用。**图标只有一处定义**，两边不会漂。

## 三个视图

**智能问答**：顶部一条**权限对照条**（`.identity-bar`），下面是两栏（**等高**）——
左 280px 历史会话卡，右对话卡。

对照条一行装四张工牌胶囊，每张写着「可见 N 篇 / 裁掉 M 篇」，右边一句提示它有什么用。
**它就是产品核心结论的可视化**：同一个语料库，四张牌能看见的篇数不一样——权限在检索之前
就把东西裁掉了。窄屏折成一行横滑（折成四行会吃掉两百像素首屏）。
两栏的高度都是 ``calc(100vh - 顶栏 - 56px)``，各自内部滚动——
左边会话多了不会把右边顶下去。这一条踩过坑：卡片默认的 ``.card + .card`` 上边距
会在网格里把第二张往下推 16px，得显式在 ``.qa`` 里清掉。

一轮问答 = **头像 + 气泡**：用户靠右（蓝色气泡 + 蓝色头像），助手靠左（白气泡带描边和浅影
+ 紫色头像）——和完整版 `ChatHistory.tsx` 的排版一致。气泡下面是状态标签行 + 折叠面板 + 反馈图标。
**受控响应**（证据不足 / 冲突 / 需人工）不渲染成散文，而是在气泡里给一条警示：
这几种情况下"答案"本身就不该被当成答案读。
`[N]` 角标是蓝色上标，点击把证据抽屉拉到"出处"页。
证据（目录 / 出处 / 轨迹）在**抽屉**里，不在常驻第三栏——常驻会把中间挤窄，
而完整版也是抽屉。换工牌时抽屉只刷新内容、不自动弹出。

**知识文档**：页面头 + 选项卡（已入库文档 / 文档上传）+ 统计卡 + 表格 + 切块实验台。
表格首列是「文件名 + 登记号」两行；隔离行整行极淡红底，下一行是可展开的信号列表；
操作是蓝色文字链接「查看分块 / 删除」（删除要二次确认）。
`查看分块` 开抽屉，抽屉读完后把正文灌进实验台。
抽屉里每块标出**标题路径**（`chunk.heading`）——切完块之后，"这块从文档哪一节切下来"
就只存在这个字段里，不显示出来等于白算。

**评测治理**：页面头 + 蓝色说明条 + 统计卡（跑过才有）+ 用例表 + Ragas 三指标 + 历史报告。
用例行可点，详情开抽屉；未跑的格子用 `--text-4` 淡化，不假装是数据。

## Structural rules

- **同一个数字只能有一个出处**：工牌卡的「可见 N 篇」和目录接口的「可见 N 篇」
  曾经从两处算（前者遍历写死的 `DOC_POLICY`，后者遍历真实切块账），于是同一页上
  一个说 5、一个说 6。现在都走 `acl_matrix.corpus_sources()`——**同一页上同一个数字
  出现两个值，读者会开始怀疑哪个都是错的**。
- **索引形状版本由零件拼出来，不是手写的数字**：`INDEX_SCHEMA = f"acl-v2+{CHUNKER_VERSION}"`。
  切块策略变了但没人记得改版本号时，增量同步会认为"内容哈希没变，跳过"——于是 BM25 语料
  用新切法、向量库还留着旧切块的向量，**两路索引对"一块是什么"的理解不一致**。这比索引过期
  更糟：它不报错，只是悄悄不匹配。版本号放在切块代码旁边（`chunking.py`），改的人顺手就改了。
- **先按相关度装箱，再对装进来的做首尾编排**：顺序反了会静默丢掉第二名。`order_contexts`
  为了对抗 lost-in-the-middle 把榜眼放到列表最末，而 `_pack_hits` 按预算从尾部截断——
  预算一紧，第一个被砍的正是最该给模型看的那块。
- **登记号是入库时烙上的，不是行号**：删掉一篇不会让后面的号往前挪，空号留着。
  它现在退到文件名下面那行小字里——形式变了，这条不变量没变。
- **权限在服务端生效，前端只把话说明白**：403 时抽屉/面板里写清"切到公司管理员工牌"，
  并给一个能直接切的按钮。
- **工牌只有一份真相**：工作台在 `/whoami` 校验完之后广播一次，控制台对齐；
  两边各带请求序号丢弃过期响应。
- **没跑出来的格子不许装成数据**。
- 窄屏（≤991px，与完整版 `lg` 断点一致）侧边栏变抽屉 + 遮罩；工牌横排可滑不折行。

## Motion

`--motion-fast: 160ms`、`--motion-normal: 220ms`、`--ease: cubic-bezier(0.2,0,0,1)`
——三个变量都和完整版 `index.css` 同名同值。
只有三处动效：抽屉滑入、统计卡 hover 上浮 2px、折叠箭头旋转。
`prefers-reduced-motion` 全部关掉。

## Contracts

- `forge_lite/contracts.py` 的 `DOM_IDS` 是页面与 JS 的唯一 id 契约，测试逐条校验；
- `forge_lite/core/labels.py` 是文案表，状态/路由/角色/部门的中文标签统一从这里出；
- 静态资源零构建：`console.css` + `workbench.js` + `console.js`，浏览器直接加载，没有 npm。
