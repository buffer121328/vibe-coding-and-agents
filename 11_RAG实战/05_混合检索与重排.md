# 11.5 搜不准、搜不全怎么办？—— 混合检索与重排

> **痛点场景**：你辛辛苦苦建好了向量库，一测却发现两个致命问题——
> ① **搜不全**：用户搜设备报错码 `ERR-404-X9`，向量检索因为“语义相近”把 `ERR-NETWORK-9022` 也捞出来了，唯独漏了精确命中那个；
> ② **搜不准**：检索回来 Top-3 里有两篇是“看起来相关其实跑题”的噪声。
> 本节就用「混合多路召回 + RRF 融合 + Cross-Encoder 重排」这套工业级组合拳解决它。

---

## 🩹 痛点：向量检索的两大阿喀琉斯之踵

| 检索方式 | 强项 | 软肋 |
| :--- | :--- | :--- |
| **向量检索（Dense）** | 语义泛化强：“难过”能召回“悲伤” | 精确型号/编号/专有名词容易“记错字面” |
| **关键词检索（BM25）** | 字面精确命中强：抠死货号、编号 | 同义词/口语表达完全失效 |

> 💡 **比喻**：向量检索是个擅长“意会”的文科生，BM25 是个“抠字眼”的理科生。单独用谁都会翻车，让两人合作（混合检索）就稳了。

---

**为什么要分“粗排 + 精排”两段？** 重排模型精度高但很贵（要对每篇文档实时交叉计算），所以先让便宜的检索器快速捞出 Top-20，再让贵的重排器只对这 20 篇精排取 Top-3。

---

## 🧑‍💻 代码实现一：自己手写 RRF 融合（看透算法本质）

> 很多人只会调 `EnsembleRetriever`，却不知道它内部在算什么。这里我们**自己实现一遍 RRF（Reciprocal Rank Fusion，倒数排名融合）**，把算法的“魂”看清楚。

```python
from typing import List, Dict

def rrf_fuse(rankings: List[List[str]], k: int = 60) -> Dict[str, float]:
    """把多路检索结果的排名（每路是 doc_id 列表）融合成综合得分。
    公式：score(d) = Σ 1 / (k + rank_m(d))
    """
    scores: Dict[str, float] = {}
    for ranking in rankings:                     # 遍历每一路检索器
        for rank, doc_id in enumerate(ranking, start=1):
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank)
    return dict(sorted(scores.items(), key=lambda x: x[1], reverse=True))

# 演示：向量路与 BM25 路各自返回的排名
dense_rank = ["doc_A", "doc_B", "doc_C", "doc_D"]
bm25_rank = ["doc_E", "doc_A", "doc_D", "doc_B"]

fused = rrf_fuse([dense_rank, bm25_rank])
print("=== RRF 融合结果（按得分排序）===")
for doc_id, score in fused.items():
    print(f"{doc_id}: {score:.4f}")

# 观察：doc_A 两路都排前列 → 得分最高；doc_E 只在 BM25 排第一 → 也不低
# 这正是 RRF 的价值：不比较两路的“绝对分数”（量纲不同），只比较“名次”
```

> 💡 **为什么不能直接加分？** 向量的余弦分数在 [0,1] 之间，BM25 分数可能是 18.5、3.2 这种任意正数——两者量纲完全不同，直接相加等于“把米和公斤加在一起”。RRF 抛弃绝对分数、只看名次，科学多了。

## 🧑‍💻 代码实现二：完整「BM25 + 向量 + RRF + 重排」流水线

```python
from langchain_community.retrievers import BM25Retriever
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain.retrievers import EnsembleRetriever   # 生产直接用官方 RRF 封装
from langchain_core.documents import Document
from sentence_transformers import CrossEncoder

# 1. 模拟一份“既有精确编号、又有语义描述”的知识库
docs = [
    Document(page_content="设备 RX-9000 在高温 80 度运行时会出现告警代码 ERR-404-X9，请立即切断电源冷却。", metadata={"id": "doc1"}),
    Document(page_content="RX 系列通用维修指南：遇到常规报警请检查保险丝与散热风扇。", metadata={"id": "doc2"}),
    Document(page_content="售后退换货政策：数码产品在购买 7 天内支持无理由退换。", metadata={"id": "doc3"}),
    Document(page_content="网络模块 NW-2000 出现 ERR-404-X9 时需重启并升级固件。", metadata={"id": "doc4"}),
]

# 2. 双路检索器
vectorstore = Chroma.from_documents(docs, OpenAIEmbeddings(model="text-embedding-3-small"))
dense = vectorstore.as_retriever(search_kwargs={"k": 3})
sparse = BM25Retriever.from_documents(docs)
sparse.k = 3

# 3. 官方 RRF 封装（内部就是上面手写的算法）
ensemble = EnsembleRetriever(retrievers=[dense, sparse], weights=[0.5, 0.5])

query = "RX-9000 报 ERR-404-X9 故障怎么解决？"
candidates = ensemble.invoke(query)
print(f"粗排召回 {len(candidates)} 篇")

# 4. Cross-Encoder 重排：把 Query 和每篇文档拼在一起做深度交叉
reranker = CrossEncoder("BAAI/bge-reranker-base")
pairs = [[query, d.page_content] for d in candidates]
scores = reranker.predict(pairs)
ranked = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)

print("=== 重排后 Top-2 ===")
for doc, score in ranked[:2]:
    print(f"[{score:.4f}] {doc.page_content}")
```

---

## 🎯 为什么 Cross-Encoder 能“碾压”双塔？

| 架构 | 流程 | 精度 | 速度 |
| :--- | :--- | :--- | :--- |
| **Bi-Encoder（双塔）** | Query 和 Doc 分别过 Embedding，最后算一次余弦 | 中等（没有词级交互） | 极快（向量可离线算好） |
| **Cross-Encoder（重排）** | `[CLS] Query [SEP] Doc` 拼一起过 Transformer，逐词交互 | 极高（能捕获细微逻辑关联） | 慢（只能对少量候选打分） |

**工程定位**：双塔负责“海选”（对全库），Cross-Encoder 负责“决赛”（对 Top-20），各司其职。代表模型：[BGE-Reranker](https://github.com/FlagOpen/FlagEmbedding)、Cohere Rerank。

## 🚀 拓展：上下文压缩（Context Compression）—— 防止“上下文污染”

检索回的 Top-K 里常有“一半有用一半废话”，直接全塞给 LLM 会稀释注意力。可以在生成前再加一道**压缩/筛选**：

```python
from langchain.retrievers.contextual_compression import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor
from langchain_openai import ChatOpenAI

# 用 LLM 把每篇文档里“与问题相关”的片段单独抽出来，剔除无关废话
compressor = LLMChainExtractor.from_llm(ChatOpenAI(model="gpt-4o-mini", temperature=0))
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor,
    base_retriever=ensemble,   # 复用上面的混合检索器
)

# 生产建议：先用便宜的启发式（截断/去重/按元数据筛）再上 LLM 压缩，控制成本
```

**一句话总结本节**：检索不准不全，就用「混合多路召回 → RRF 融合 → 重排 → 上下文压缩」这条工业级流水线，把“粗（廉价海量）”和“精（昂贵精准）”组合成最优性价比。
