# 第六章：Trae 已有项目改造

本章使用 [Trae](https://www.trae.ai/)继续开发第五章的个人博客，依次增加账号权限、评论点赞和 AI 辅助写作，最后讨论代码分层。接手已有项目时，先确认现有功能，再控制本次改动范围。

## 开始前的准备

先确认第五章博客能启动、能保存文章，再进入本章。配套目录包含后续阶段成果；若要逐步重做，应从第五章项目副本开始，并与本章的规格及代码对照，避免把已经存在的功能当成新实现。

## 阅读顺序

1. **[6.1 认识 Trae 与代码审查方式](./01_初识Trae：双模驱动、新人福利与生产级IDE新范式.md)**
   - 从修改范围、功能行为和验证证据三个角度审查结果。

   - 区分当前规格与历史资料，确认依赖、测试和页面运行状态。
3. **[6.3 用户登录与操作权限](./03_阶段一实战：用户认证与JWT权限隔离系统.md)**
   - 区分认证与授权，覆盖接口操作和数据可见范围。
4. **[6.4 评论、点赞与分页改造](./04_阶段二实战：评论点赞系统与接口分页重构.md)**
   - 处理重复请求、排序稳定性、空页与所有接口调用方。
5. **[6.5 AI 摘要与标签生成](./05_阶段三实战：AI原生赋能智能摘要与自动打标.md)**
   - 校验输出，保留人工内容，理解进程内后台任务的限制。

## 怎样判断改造完成

| 范围 | 至少检查什么 |
| --- | --- |
| 原有功能 | 新增功能后仍能创建、读取、编辑和删除文章 |
| 用户权限 | 未登录、普通用户、管理员分别能做什么 |
| 评论与点赞 | 重复请求、删除关联数据、失败提示 |
| 分页 | 排序、空页、总数与页面读取方式一致 |
| AI 生成 | 未配置模型、调用失败、人工内容保留 |
| 目录调整 | 启动方式、数据库位置、静态资源与原接口兼容 |

文中的测试数量与截图属于案例记录，当前版本应重新运行检查。6.6 的目录树是重构参考方案，新增章节中的可靠任务与版本校验也是扩展方向，不代表配套代码已经完成这些改造。

## 每个阶段都保留四项记录

本章是在已有博客上连续改造，后一阶段会继承前一阶段的决定。为了分清问题从哪里引入，每个阶段开始和结束时都建议保留以下记录：

| 记录 | 应包含的内容 |
| --- | --- |
| 基线 | 当前代码状态、依赖、测试、启动方式和已知失败 |
| 变更范围 | 本阶段新增行为、不得改变的接口与数据 |
| 验证证据 | 自动检查结果、一次完整人工操作及异常场景 |
| 回退说明 | 数据结构是否变化、怎样恢复原配置或代码 |

6.2 建立项目基线，6.3—6.5 分别增加权限、互动和 AI 辅助能力，6.6 再讨论结构调整。阅读时应持续对照同一批原有功能，确保新增能力没有破坏文章的基本增删改查；结构重构则要复用前几节积累的用例，验证外部行为仍然一致。
