# 1.4 AI 原生 IDE 时代：让对话与项目现场连接起来

装修师傅如果一直通过电话听你描述房间，很容易弄错尺寸；到现场看过门窗、水电和图纸，建议就会具体得多。AI 与编辑器结合，也是为了让模型更容易接触当前项目的真实信息。

IDE 指集成开发环境，把编辑、运行、调试等功能放在同一处。所谓“AI 原生 IDE”，通常指围绕 AI 协作设计主要操作流程的开发工具。它不是一个严格统一的技术分类，也不能据此断言插件一定比独立编辑器弱。

## 项目上下文是怎样提供给模型的

编辑器可能提供当前文件、选中的代码、目录结构、搜索结果、诊断信息和终端输出。有些工具还建立索引，帮助从大量文件中找出与问题相关的片段。

这里的索引像图书馆目录：它帮助定位资料，但不代表管理员已经记住每一页。模型通常只收到经过选择的一部分内容；被忽略的文件、未保存的更改、生成文件和检索遗漏，都可能影响判断。

因此，“支持整个代码库”更准确的理解是“能够在项目范围内查找与读取信息”，而不是“每一轮都完整理解了所有文件”。

## 从改一个按钮到改一条业务流程

假设要在笔记列表中增加“收藏”功能。只给按钮换个图标不难，但完整功能还涉及收藏状态存在哪里、刷新后是否保留、列表如何筛选。

可以先让 AI 查找以下内容：

1. 笔记列表页面和单条笔记组件；
2. 笔记数据结构，以及存储或接口定义；
3. 已有的类似交互和相关测试；
4. 项目对样式、错误提示和命名的约定。

确认这些位置后，再安排修改。这样能减少重复创建组件、绕过现有接口或者另起一套存储逻辑的情况。

## 几种交互方式怎样配合

| 方式 | 适合处理 | 使用时留意 |
| :--- | :--- | :--- |
| 代码补全 | 已经知道实现位置的小片段 | 建议是否沿用正确字段 |
| 选中代码修改 | 一个函数或局部页面调整 | 是否只影响选定范围 |
| 项目问答 | 理解目录、调用关系和设计 | 回答是否引用了实际文件 |
| 跨文件修改 | 接口、数据和界面联动 | 是否漏改调用方或测试 |
| 智能体执行 | 运行检查、读日志、继续修复 | 执行位置和结果是否明确 |

这些模式的名称与快捷键会随产品版本调整。先理解用途，再在当前界面中寻找对应入口，比记住某个固定按钮位置更实用。

## 为什么仍然需要查看修改差异

修改差异会显示新增、删除和改动的内容。它像装修前后的对照照片，帮助你确认施工是否超出约定范围。

如果只要求加一个收藏按钮，却出现大量依赖升级、目录搬迁和格式重写，就应先弄清原因。变化越多，验证范围越大。合理的改动应能解释每个文件为什么需要修改。

对初学者来说，不必一次读懂整个项目。可以先检查三点：改动是否对应需求，原有功能是否保留，验证是否真正执行。发现看不懂的关键逻辑，再请 AI 结合实际输入解释。

## 常见工具入口

- [Cursor](https://cursor.com/docs)：查看项目上下文和编辑功能。
- [Windsurf](https://windsurf.com/)：了解其编辑器及协作方式。
- [Trae](https://www.trae.ai)：查看对应地区版本的功能与账户说明。
- [Zed](https://zed.dev/docs)：了解编辑器与 AI 集成。
- [JetBrains AI](https://www.jetbrains.com/ai/)：了解既有开发环境中的 AI 能力。

选择时可先考虑自己熟悉的操作习惯、项目语言和实际可用的模型。已有编辑器能够完成工作，就没有必要仅为“原生”两个字重新迁移。

## IDE 与 Coding Agent 的关系

IDE 是工作界面，Coding Agent 是执行任务的系统能力。智能体可以放在编辑器侧栏、终端、桌面应用或云端环境中。现在许多 IDE 已能运行终端并循环修复问题，因此二者的区别不应被描述为“一个只能建议，一个才能执行”。

下一节会把注意力从界面转向执行过程：任务怎样被拆解，工具怎样被调用，系统怎样判断应该继续还是停止。
