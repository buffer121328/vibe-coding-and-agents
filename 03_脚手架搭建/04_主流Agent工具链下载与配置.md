# 3.4 主流 Agent 工具：安装、接入与首次任务

购买一套工具之后，先在一小块材料上试用，比直接加工整件家具更容易判断是否顺手。安装编码智能体也一样：先完成读取项目、修改一个小文件和检查结果，再逐步增加复杂任务。

本节提供入口与通用检查方法，后续章节再分别开展项目实战。按钮名称、订阅范围和安装方式可能变化，具体操作应以当前官方文档为准。

## 按使用方式选择一个入口

| 使用方式 | 工具与官方入口 | 先确认什么 |
| :--- | :--- | :--- |
| 在编辑器中操作 | [Trae](https://www.trae.ai)、[Cursor](https://cursor.com/docs) | 项目打开位置、账户和模型设置 |
| 在已有编辑器中安装扩展 | [Cline](https://docs.cline.bot/) | 发布者、模型提供方与执行权限 |
| 主要使用终端 | [Claude Code](https://code.claude.com/docs/en/overview)、[OpenCode](https://opencode.ai/docs/) | 安装方式、认证、工作目录 |
| 使用 Codex | [Codex 官方文档](https://developers.openai.com/codex/) | 所选入口、登录方式与项目上下文 |

工具安装成功与模型服务开通是两件事。某些入口支持产品账户登录，某些支持自带密钥；是否可用取决于具体工具和账户权益，不能默认免费或不受限制。

## 编辑器类工具的准备步骤

从官网下载对应系统安装包，启动后打开完整项目目录。只打开单个文件时，工具可能缺少其他代码、配置与说明。

然后确认模型连接与项目上下文。可以先问：“请读取项目说明，列出主要目录、启动方式和测试入口，并注明依据的文件。”这次任务不需要修改代码，能帮助检查它是否真的看到了项目。

如果回答只有通用介绍，没有引用现有文件，再检查打开位置、访问权限或索引状态。索引尚未完成时，也可以明确提供关键文件，避免让模型根据文件名猜测内容。

## 终端工具的安装与验证

安装前先阅读所选工具的官方要求。不要把某个旧版本的 Node.js 依赖要求当作所有工具的通用前提。例如 [Claude Code 安装说明](https://code.claude.com/docs/en/setup)提供原生安装与不同系统的包管理方式；按当前系统选择一种即可。

安装完成后，可以用版本命令确认终端找到的工具，再进入自己的项目：

```bash
claude --version
cd /path/to/your-project
claude
```

`/path/to/your-project` 是占位路径，必须换成自己的项目位置。首次启动按照工具提示完成认证，不需要将密钥粘贴到聊天正文里。

OpenCode 按其[官方入门文档](https://opencode.ai/docs/)安装并连接提供方，再进入项目启动。不同工具的配置文件、环境变量和会话目录不同，不应互相复制。

## 配置自定义模型时，核对四项信息

以支持自定义服务的客户端为例，需要核对提供方、Base URL、API Key 和模型标识。选择了官方提供方时，通常由客户端处理部分默认参数；选择兼容接口时，则应使用对应服务的文档。

填完之后先发一个短请求。短请求成功，只证明基本连接可用；如果后续要做编码任务，还要验证工具调用、流式输出和上下文支持。

不要一次同时更换模型、代理和插件。如果调用失败，逐项调整才能知道是哪一项配置起作用。

## 第一项任务：让 AI 改一处可以独立验证的内容

可以选择项目说明中的一个错别字，或者一个不涉及外部服务的小函数。任务示例：

> 请先读取项目说明和相关规则，将指定页面的标题改为“我的读书笔记”。保持其他内容不变，完成后列出修改文件，并说明怎样在本地查看结果。

检查它是否定位到了正确文件、改动是否只涉及目标，以及提供的运行步骤是否与项目一致。第一次体验不必直接安排用户登录、支付或大规模重构，这些任务涉及更多前置条件，难以区分是配置问题还是实现问题。

## 第二项任务：验证它能正确使用工具

在已经配置好环境的练习项目中，让智能体执行现有的一个检查，例如读取解释器版本或运行一条明确的测试命令。观察执行记录，而不仅是最终回复。

如果命令失败，要求它说明错误和原因依据；不要让它把“没有运行测试”写成“测试通过”。没有测试的项目也不必伪造测试结果，可以清楚记录实际采用的手动检查。

## 建立适合自己的协作习惯

- 一个任务对应一个清楚的目标，较大需求先拆分。
- 允许工具执行什么，按项目需要设置，并观察每次变更的范围。
- 实现之后查看差异，再核对实际结果。
- 把稳定的运行方法与约定写进项目文档，减少重复说明。
